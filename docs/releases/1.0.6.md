# dsh-code Release Notes - 1.0.6

## Overview

1.0.6 upgrades the terminal to the dsh 0.1.5-rc.1 line and adopts session-log format v3 on the reading side. Old sessions keep working exactly as before: logs written by earlier releases load through an in-memory migration, and the files on disk stay byte-for-byte unchanged. Alongside the alignment, the terminal gains file attachments, fuzzy completion for `/` and `@` menus, provider configuration diagnostics on the /model pages, skills in the slash menu before the first message, and a one-command upgrade that carries every plugin the cli profile installed onto the new harness line. An adversarial audit across the alignment fixed a broken feature (/fork) and several interaction defects, and a startup React update loop triggered by the burst of registry events the new host emits was fixed alongside.

## New features

### File attachments beside images

- A terminal paste or drop now splits by kind: images stay image blocks, and any other path-shaped entry (drive letter, UNC, `file://`, or a dot-suffixed leaf after a separator) becomes a durable file attachment sent verbatim. Prose, slash commands, and bare words stay plain text; a mixed paste never attaches only part of its content.
- Bounds are explicit: one file up to 8 MiB, at most 8 files per message.
- The composer manages file drafts exactly like image drafts: visible `[file: name · bytes]` markers, deletion follows the marker, Ctrl+C clears everything, and submission prepares both kinds in parallel.
- The transcript, Ctrl+O details, and /export show file labels next to image labels on both settled and queued rows.
- Commands cannot carry attachments: submitting a slash line with attachments attached now shows a clear notice and still sends the line to the model as a prompt, as before.

### Fuzzy completion and pre-session skills

- `/` and `@` menus match by ordered subsequence, case-insensitively, with prefix hits ranked first — the same ranking the web client uses. `/md` finds `/mode`; `@pk` moves `package.json` to the top.
- The mention menu reorders without dropping rows: rows the upstream matcher still returns keep their place after the promoted hits.
- Skills appear in the `/` menu from the very first screen, before any session exists: the skill registry reads its global layer for the working directory at startup and upgrades to the session-scoped view once the first session begins. Model-facing skill invocation is unchanged — it still mounts per session with the selected preset.
- Registry commands still arrive with the first session (the host list call requires an agent); the built-in local commands cover the gap.

### Provider configuration diagnostics

- A provider whose configuration is damaged no longer vanishes from /model: the adapter's error rides the provider row, the list appends it to the label, and the unified setup page shows it under the title in the warning color — the provider stays listed and repairable.

### The effective system prompt becomes visible

- /export emits the current system prompt as a collapsed block between the session header and the first entry, so persona changes can be reviewed directly.

### /agents gains durable catalog rows

- Each child the session spawns can appear as an idle row carrying the label and mode the catalog recorded, alongside the existing live-activity rows.

### `deepseek update` carries the whole profile

- Plugins installed into the cli profile through `dsh plugin add` now upgrade to the new harness line in the same `update --apply` run — one command moves the host, dsh-code, and every companion plugin together. Community packages outside the @deepseek-ai scope are never touched.
- The updater refuses to downgrade an installed host to the line an older published dsh-code pins, and prints the manual command instead of silently moving the environment backward.

## Upstream alignment: dsh 0.1.5-rc.1

### Session-log format v3 on the reading side

- Logs written by earlier releases load through an in-memory migration at read time; the files on disk are never rewritten, and multiple generations may coexist in one session directory untouched.
- Live typing and the durable log separated: the transcript store now folds process-local assistant-stream frames for streaming, while settled messages restore their text and first-token timings from the embedded stream record. Replaying a session produces the same view and the same latency statistics as the live run.
- The system prompt became a first-class surface message; the context estimate follows it and stays honest across compaction, because any surface replace now retires the system nodes its range covers.
- `/fork` records lineage through the new contract fields; the previous spelling is rejected outright by the released kernel.

### Host-side gains that arrive with the line

- The model catalog adds DeepSeek-V41-Flash and makes it the default for new sessions; discovery can list models over the anthropic-messages protocol and understands more gateway fields; broken provider catalogs degrade into visible diagnostics instead of disappearing.
- Proxy environment variables reach child processes; MCP tool pagination detects continuation-cursor cycles; tool interruption on Windows terminates process groups immediately through Job Objects.
- Model switches now append a durable notice row to the transcript.
- The kernel's per-session projection cache accelerates cold session listings.

## Fixes

- Opening the terminal on the new host printed "Maximum update depth exceeded" warnings before any input: the command-registry notifications churned a fresh array identity per event into React's update chain. The watcher now keeps the previous identity when the catalog is unchanged and coalesces notifications; the skills error path and the subagent catalog fold follow the same rule.
- An attachment submission prepared while a queued session switch landed could deliver into the newly switched session; deliveries now carry the composing session's identity and the runner drops the stale ones.
- A compaction summary could leave the system-prompt estimate counting retired nodes; the estimate now follows the surviving assembly.
- A late subagent catalog delivery could regress a finished child row to idle and lock it out of eviction; catalog rows keep the row's state and a full feed evicts the oldest non-running row so new children stay visible.
- /delete counts an unreadable directory as a failure instead of a silent success.
- The setup page's diagnostic row joins the panel height budget.
- The launcher's line-ordering, host-version probe, and plugin-carry steps are covered by tests; the bilingual upstream audit records the full alignment.

## Verification

- 788 automated tests across 54 files, typecheck, build, a clean peers check, and `pnpm pack --dry-run` all pass; the cli profile was removed and reinstalled with `--help` and `--dump-config` verified after every stage.
- Sessions written by earlier releases were loaded through the in-memory migration with on-disk files unchanged; streaming, retry statistics, and resumed views were checked to match the live run.
