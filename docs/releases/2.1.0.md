# dsh-code Release Notes - 2.1.0

## Overview

2.1.0 aligns DSH-Code with DeepSeek Harness `0.2.1-rc.4`. The model picker discovers subscription models beyond the installed catalog and can import selected Codex candidates into Harness. The status bar follows working-directory changes, and terminal fixes keep asynchronous catalog diagnostics out of the welcome header.

## Model discovery and selection

- `/model` supplements registered models with the DeepSeek Account model listing and pi's public Codex catalog. Failed catalog requests keep the registered models available; Codex discovery can also use pi's local catalog cache.
- Remote-only Codex models appear as candidates. Enter imports a selected candidate through Harness settings before applying it, preserving existing models and customizations. Conflicting or read-only provider settings produce an error instead of being overwritten.
- Codex catalog entries carry validated context limits, input types, and reasoning levels. Registered models keep their adapter-owned capabilities; unsupported reasoning levels are not offered after import.
- Catalog results are cached for four hours. Refreshing `/model` bypasses the Codex catalog cache. Codex discovery uses public catalog data and does not read pi's OAuth credentials; requests continue to use the configured Harness provider.

## Working directory, presets, and language

- The directory and Git branch in the status bar follow committed working-directory changes, including when a session is resumed.
- The `standard`, `ptc`, and `cordis` presets follow upstream clock-context declarations. The `minimal` preset gains image reading and its own context-compaction group. Reminder tools still require the Web delivery services and are unavailable in this terminal composition.
- Chinese panel labels and permission preset names follow the upstream terminology. The primary README is English, with Chinese documentation in `README_CN.md`.

## Terminal fixes

- Asynchronous console diagnostics use the same cursor-restoration path as Ink output, so account model-listing messages no longer overwrite the welcome header when the IME cursor is positioned in the composer.
- Ink resynchronizes its row ledger after an oversized frame and resets accumulated Static output when history is remounted, preventing stale rows and duplicate history in those recovery paths. Transcript budgeting includes the actual status bar height.
- On macOS Terminal.app, full blocks in the whale header use background-colored cells to avoid gaps caused by line spacing. Half-block outline alignment remains imperfect in that terminal.

## Compatibility and upgrade

The release tarball bundles audited production dependencies so installation retains the patched copies. The package is larger as a result. Host dependency repair is a separate installation step, shown below.

- Requires Node `^22.19 || >=24` and exactly `@deepseek-ai/dsh@0.2.1-rc.4`. Upgrade the host, DSH-Code, and any separately installed Harness profile plugins together. The old rc.2 or rc.3 host cannot load this bundle.
- `deepseek repair-deps` repairs the existing host installation with scoped overrides for Zod `4.6.6`, Undici `8.12.2`, MCP client `2.3.0`, and fflate `0.8.3`. It backs up metadata, preserves the Harness release, verifies active resolution paths, and runs a production dependency audit. Setup and updates include this step; rerun it after a manual host reinstall. `deepseek repair-deps --check` and `deepseek doctor` check active versions without changing files.
- Harness 0.2.1 removes the `{{cwd}}` prompt variable and retired invariant and Ralph rows. The bundled presets are updated; remove those obsolete entries from custom profile patches. The working directory is provided through runtime context.
- Claude Code and Codex hooks bridges are no longer bundled by the host. If used, install the bridge and `@deepseek-ai/dsh-hook-protocol`, both at `0.2.1-rc.4`, into the profile. See the [upgrade troubleshooting table](../installation.md#upgrade-troubleshooting).

Close all running `dsh` and `deepseek` sessions before upgrading. For an npm installation:

```sh
npm install -g --allow-scripts=@deepseek-ai/dsh-subprocess-local,koffi,node-pty,@google/genai,protobufjs @deepseek-ai/dsh@0.2.1-rc.4
npm install -g dsh-code@2.1.0
deepseek repair-deps
dsh plugin --profile cli add dsh-code@2.1.0
```

If the profile separately lists `@deepseek-ai/dsh-tool-session-query`, update it too:

```sh
dsh plugin --profile cli add @deepseek-ai/dsh-tool-session-query@0.2.1-rc.4
dsh --profile cli --dump-config
deepseek doctor
```

Check that the composition has no version-mismatch, `skipping`, or `disabling` diagnostics. For a local `link:` checkout, rebuild with `pnpm install && pnpm build` and keep the local mount; do not replace it with the npm bundle. See [installation and upgrade troubleshooting](../installation.md) for profile migration errors.
