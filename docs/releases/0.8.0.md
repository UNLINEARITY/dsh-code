# dsh-code Release Notes - 0.8.0

## Overview

Version 0.8.0 makes provider setup a first-class terminal workflow and hardens dsh-code for long-lived sessions. A DeepSeek API key is no longer presented as a startup prerequisite, `/model` can manage provider credentials through Harness, pre-session `/mode` and `/permission` controls land with a redesigned status bar, GFM tables and multiline reasoning render cleanly, and large persisted transcripts restore with near-linear work. Streaming reliability fixes silence nested-update warnings during reasoning-heavy models, and session switching, recall persistence, terminal text boundaries, and settled-history rendering all receive focused fixes.

## New features

### Provider and credential management

- `DEEPSEEK_API_KEY` is no longer documented as a startup prerequisite. The Harness keyless path remains available for opening the TUI, inspecting or resuming sessions, using non-model features, and browsing the model catalog; missing credentials fail only when an inference is attempted, with a direct hint to open `/model`.
- Press `a` in `/model` to open the provider panel. It can add or rotate a masked API key, remove a writable key, activate a configurable provider, and remove a user-added provider profile without introducing a second credential store.
- Credential status is intentionally value-free: the panel shows only whether a key is configured, its source, and whether it is writable. Environment-provided keys remain visible but read-only, and credential, settings, or adapter changes refresh the panel while it is open.

### Pre-session mode and permission controls

- A fresh TUI now shows the configured default agent mode and permission preset before any session exists. `/mode`, `/permission <preset>`, and Shift+Tab can change those pending choices without creating an empty persisted session; the first real message composes its session with the selected values. Both commands are listed in `/` completion and `/help`.
- Typing bare `/permission` opens a bounded preset picker mirroring the `/mode` panel — filter by typing, arrows to move, Enter to apply, `r` to refresh, Esc to close — while `/permission <preset>` keeps its direct one-line path.
- Agent mode remains locked after the first durable turn, following the Harness preset contract. Permission presets remain changeable after session creation and continue to write through Harness-owned session events.

### Terminal rendering

- The primary status row now follows model, working directory, `/mode <value>`, Git branch, context, then the right-pinned permission preset with the Shift+Tab hint. Session title, counters, timings, cache, tokens, goal, plan, and sandbox state move to the second row, indented to line up with the model name's left edge under its own width budget.
- The context meter is now a stepless bar: a solid fill run, a dotted free track, and the usage readout (`32K/128K 25%`, shrinking to the bare percent as space narrows), replacing the per-content-type segmented bar. The readout flips to amber at the 90% warning threshold.
- GFM pipe tables render as measured, borderless terminal grids with emphasized headers, column alignment, escaped pipes, and inline Markdown. When a terminal is too narrow for a readable grid, the same data switches to a field-record layout instead of discarding cell content.
- Finalized, inspected, live, and streaming reasoning now share a hanging indent, so explicit line breaks and wrapped continuation lines stay aligned with assistant reply text.
- The welcome area now shows the installed package version in a compact three-line whale header, followed by the bilingual slogan `Into the Unknown  探索未至之境`. Short or narrow terminals retain a safe one-line fallback.

## Reliability and performance

### Session lifecycle and recall

- Session composition is serialized, and asynchronous mention, command, and skill results are gated by the active Agent epoch so stale work cannot cross a session switch.
- Resume handling consistently rejects subagent conversations and session ID collisions, uses platform-aware working-directory matching, and sanitizes generated export suffixes.
- Global prompt recall is capped at 100 entries and writes the latest in-memory snapshot through a serialized queue. Quit now awaits ordered cleanup while still reaching process exit when an individual cleanup step fails.

### Long transcripts and terminal safety

- Persisted transcript replay now uses indexed mutable accumulation followed by one final materialization, replacing copy-on-write array rebuilding. Long and orphan-heavy logs scale near-linearly while preserving the live reducer's behavior for duplicate IDs and interrupted records.
- Streaming token bursts (a provider draining its buffer in sub-millisecond groups) now coalesce into one re-render per burst. Synchronous per-token notification previously cascaded React's store-consistency checks past the nested-update limit and flooded "Maximum update depth exceeded" warnings during reasoning-heavy models such as GLM.
- Running commands remain in the mutable tail until completion, so their final status appears immediately instead of waiting for a resize. Finalized transcript rows are cached incrementally, queued-message scans stay within the changeable tail, and composer animation frames no longer rebuild settled history.
- External tool, command, panel, and history text is escaped and normalized before terminal rendering, including OSC/CSI bytes, bidirectional controls, invisible Unicode, multiline text, and tabs. Diff expansion, read/source metadata, and large structured tool arguments are bounded before expensive parsing or allocation.

## Refinements

- DeepSeek Wave, Aurora, and Pulse model-switch animations run 200 ms longer with their complete timelines proportionally remapped, making the sweep, border glow, wordmark, and trailing sparkles easier to follow without adding an idle pause.
- Recoverable provider and model failures stay inside bounded panels, including the five-row short-terminal layout, without clearing scrollback or exposing submitted secrets.

## Behavior changes

- Global prompt recall now keeps the newest 100 entries instead of 500. The persisted history is compacted to that limit on the next submission.
- `/resume` and `--continue` select root sessions only; subagent conversations remain available for read-only inspection. `--session` now reports an error when its requested ID already exists instead of colliding with persisted state.
- Default `/export` filenames sanitize explicit session IDs, and quit waits for ordered persistence and Agent cleanup before exiting; an individual cleanup failure no longer prevents process exit.

## Important notes

- Upgrading from 0.7.0 requires no configuration or persisted-session migration; this release removes no commands or settings.
- Runtime requirements remain Node `^22.19 || >=24` and a compatible `@deepseek-ai/dsh` installation.
- A key is still required for model inference. Add one through `/model`, or provide `DEEPSEEK_API_KEY` when launching; environment-provided credentials cannot be overwritten or removed from the TUI.
- The package version shown in the welcome header comes from the installed `dsh-code` package manifest.
- On the release day, pnpm users should pin the exact version `dsh-code@0.8.0` because pnpm ignores packages published less than 24 hours ago.
