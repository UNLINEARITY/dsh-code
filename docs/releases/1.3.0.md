# dsh-code Release Notes - 1.3.0

## Overview

1.3.0 is a broad TUI reliability and safety release based on the complete change set since 1.2.0. File drops now become real attachments across terminal and platform path formats; panels consistently own the keyboard; session switching, forking, history recall, and streaming layout no longer lose or misroute work. Session deletion is also substantially safer: forks survive their origin's deletion, another process's live writer blocks removal, and `/delete` is now a dedicated workflow that can never resume a conversation by mistake. The host line remains `@deepseek-ai/dsh@0.1.5-rc.2`.

## Improvements

### File drops and attachments

- Dragging a file or screenshot into the composer becomes the same image/file attachment as copying the pathname and pasting it, on macOS, Windows, and Linux terminal paths.
- Filenames with spaces, Unicode quotes, shell-escaped spaces, and percent-encoded `file://` URLs resolve as one local path.
- Unbracketed file drops remain one input unit instead of being split character by character, avoiding React update-depth failures before attachment parsing.
- Drafts that look like filesystem paths no longer open slash completion, and leftover paste-control bytes are stripped before the path is inspected.
- Mention completion no longer swallows Enter when there is nothing new to accept or when the draft already spells the highlighted token.

### Panels, commands, and updates

- Every panel uses one keyboard-ownership contract. `/search` input no longer leaks into the composer, Enter no longer submits the query as a prompt, and Esc closes the panel instead of interrupting a running turn.
- Ctrl+C closes an open panel like Esc; without a panel, the existing interrupt, clear-draft, and quit behavior is unchanged. Panels displaced by an approval do not reappear after the answer.
- Local commands that accept no arguments now report `usage: /name` for extra text instead of forwarding that text to the model.
- An active `/update` installation survives panel closure and reconnects when `/update` is reopened. A second confirmation cannot start another installer, progress is retained, and Esc remains locked while installation is running.
- A failed update child now clears its shared running state without creating an unhandled cleanup rejection.

### Sessions and deletion safety

- Deleting a root session removes only the subagents it delegated. `/fork` branches are independent conversations and keep their logs; their own delegated subagents still follow the branch.
- `/delete` and `/resume` are now separate workflows. In `/delete`, Enter can only enter the explicit `y` confirmation; in `/resume`, Enter only resumes and the old `d` deletion shortcut is gone.
- Before touching any artifact, deletion acquires the persistence write handle for every member of the planned subtree. A session open in another terminal therefore blocks the entire deletion, and partial lock acquisition rolls back without removing files.
- `/delete <id>` resolves an exact id, unique prefix, or the unique suffix displayed by the picker, widening the listing scope when needed before it asks for confirmation.
- While a queued session switch is activating, a new ordinary submission is refused with a notice instead of being started on the outgoing agent and then discarded.
- Accepting a `/history` entry appends it to the current draft and preserves prepared attachments. The previous draft remains reachable through recall.
- `/resume` filtering matches displayed titles as well as ids and paths, and title loading expands for active searches.
- `/fork` anchors to the containing completed turn, including metadata gaps between turns. `/clear` during streaming clears settled history while the live response continues.

### Layout, status, and localization

- Streaming text wraps at the same column as settled Markdown, and the Ctrl+O inspector reflows to the current terminal width.
- History-cap trimming preserves native terminal scrollback; resize and Ctrl+L retain their intentional full-clear behavior.
- At common 120-column widths, the status line keeps the context meter longer by dropping lower-priority hints and identity fields first.
- Large token counts no longer render as `1000K`, hour-long durations use hours, and a missing manifest no longer displays a fake `v0.0.0`.
- Rainbow error colour no longer collides with the live busy hue, and stale `/effort` lookups cannot replace a newer model picker.
- Session, startup, copy/export, settings-warning, plan, goal, sandbox, welcome, and `/statusline` labels now consistently follow the selected English or Chinese interface language.

## Development and release safeguards

- The patched `js-yaml` release is enforced across the dependency graph, and both CI and release jobs fail on known production dependency vulnerabilities.
- ESLint now treats every warning as a failure. React Hook dependencies were made explicit, and global test retries were removed so deterministic failures remain visible.
- Coverage now has conservative global floors: 82% for lines, statements, and branches, and 88% for functions.
- Release jobs verify that the tag, `package.json` version, and both release-note files agree. The same audit, metadata, verification, and build gates run for manual `npm publish`.
- GitHub Actions are pinned to complete commit SHAs, CI uses a read-only token, pnpm is fixed at 12.4.1 locally and in workflows, and deprecated tsdown dependency options were removed without changing bundle bytes.

## Compatibility and upgrade notes

- No Harness peer line changed; `@deepseek-ai/dsh@0.1.5-rc.2` remains the supported host line.
- There are no configuration migrations.
- Workflow change: deletion is no longer available through `d` in `/resume`. Use `/delete`, select with Enter, then confirm with `y`.
- npm remains the primary channel; the GitHub Release tarball remains the fallback for restricted networks. A tag push creates the GitHub Release asset but does not run `npm publish`.

Upgrading from 1.2.0:

```sh
npm install -g dsh-code@1.3.0
dsh plugin --profile cli add dsh-code@1.3.0
```

Then `/quit` and start again. A GitHub-tarball installation can be overwritten by the npm command. Until npm carries 1.3.0, the updater reports that a 1.3.0 tarball install is newer and refuses to downgrade.
