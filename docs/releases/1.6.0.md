# dsh-code Release Notes - 1.6.0

## Overview

1.6.0 moves the terminal to the upstream `@deepseek-ai/dsh@0.1.7-rc.2` line and turns the release's new facts into terminal surfaces. Every top-level turn ends with its git-level changed-files summary (`⟳ 3 changed files · +42 −7` with per-file counts), dynamic tool loading renders one dim row (`⚙ +web-search · −lsp`), and the segmented context bar prices image content and honors image offload. Cross-session search no longer blocks: the engine runs on a persisted index under the dsh home, and both its cold reads and the title-enrichment pass carry explicit ceilings. The 0.1.7 settings migration is guarded end to end — a stranded provider/model configuration is detected at startup and re-imported through the host's own settings pipe — and reminders leave the terminal honestly rather than half-activated, because their rc.2 delivery stack exists only in the web composition.

## Upstream alignment to 0.1.7-rc.2

- Every Harness dependency moves to 0.1.7-rc.2, and the supported host line follows: the installation commands in both READMEs pin `@deepseek-ai/dsh@0.1.7-rc.2` explicitly, because npm's `latest` dist-tag for the host still points at the older line. `/update` derives the host line from this release's own peers, so the launcher, the bundle, and profile plugins always move as one aligned step.
- `dsh-llm-deepseek` is renamed `dsh-llm-deepseek-api-key` upstream, with a new `llm-deepseek-account` channel beside it; the user-layer row name follows automatically through the base composition.
- The retired agent-presets and code-runtime packages give way to the preset registry and the ptc runtime that dsh-base now ships; the bundle patch carries the four preset declarations as ordered patch files under `presets/`.
- The transcript fold reads session format v4: tool results use the flattened tool-role message, producer sources match their own kinds instead of the retired plugin wrapper, the new developer-message, image-offload, and workspace-changes events get explicit dispositions, and forked turn ends render a marker. Older session logs migrate in the kernel on read (v3 to v4); the original files on disk stay untouched. Sessions and startup arguments naming the former `code` preset map automatically to the renamed `ptc`.
- Jobs rows follow the rewritten jobs service (listed by session id), and the subagent catalog handles the new unknown mode.

## Turn-level visibility (new projections)

- Every top-level turn ends with its changed-files row — `⟳ N changed files · +a −d` followed by up to twelve per-file line counts — sourced from the host-bundled `workspace-changes` recorder (git snapshots of the turn's working tree plus file-tool captures for paths git does not cover; outside git the summary lists file-tool edits only). The row supersedes the diff-derived `⎄ files` row while its live summary lasts and falls back to it on resume; Ctrl+O inspects the enriched detail.
- Dynamic tool loading renders one dim row per developer message (`⚙ +web-search · −lsp`); text-only developer messages stay collapsed.
- The segmented context bar gains an `images` segment priced by intrinsic pixels that `image/offload` decisions subtract exactly, so the bar matches the model's view after long-context offload. Estimates drive proportions only; billing keeps reading the harness token meter.

## Cross-session search unblocked

- The search engine ran on an in-memory index, so the first search of every launch re-decompressed and re-decoded the entire persisted corpus — minutes on a few hundred zstd logs. The index now persists as a SQLite database under the dsh home (owner-only, auto-created): one full build, incremental reconciliation afterwards.
- Each persisted session's cold read carries a thirty-second ceiling; a genuinely truncated zstd frame leaves the upstream streaming decoder waiting forever without an error, and one such log could wedge every search. A timed-out read becomes one skipped source with a warning — the corpus indexes normally around it.
- The title-enrichment pass carries an eight-second budget: on expiry the result rows keep their short-id labels and match snippets instead of blocking the panel behind a heavyweight log's title fold.
- Verified end to end on a 358-session corpus: results render in seconds from a cold boot, and a fresh profile installed from the packed tarball renders its first search in 3.4 seconds after the keystroke.

## Terminal reliability

- Approval bodies show the full raw arguments of the paired tool call, wrapped within the bar's row budget with an overflow count — an approval is a security decision, and the previous 80-character card preview cut target paths to an ellipsis.
- The `/mode` list resolves shipped-preset copy through the registry's dictionary keys with the official translations (since 0.1.7 a shipped preset publishes no name or description), keeps user-authored metadata verbatim, and the typing filter matches the resolved copy.
- A source-backed replay (resize or Ctrl+L) keeps one terminal-sized real tail live instead of flushing every settled row into native scrollback — the bottom anchor no longer releases, and the next dynamic frame still shows the newest history. Fill-state counting includes the painted header.
- The update probe derives the npm global root from the running node (nvm, Homebrew, and system layouts) when no environment hint is set, so `/update` no longer reports the installed host as missing from a link-mounted checkout.

## Settings-migration safety net

- dsh 0.1.7 retires the global `settings.yaml`: the host imports it once into the booting profile's patch layer, but the import renames before it writes, has no retry, and a degraded first boot can strand sections in the renamed file. At startup the terminal compares the renamed document against the active profile's patch layer and re-imports each stranded section through the live settings service — the same validated, file-locked, hot-reloading pipe the provider panel uses — so configuration returns without manual steps or a restart.
- Only sections with no landed row are ever written: existing configuration is never touched and the recovery is idempotent. The outcome surfaces as a one-line notice; per-section failure reasons and copy-paste recovery paths go to stderr, and manual guidance appears only when the settings service is unavailable. Credentials are unaffected throughout.

## Reminders leave the terminal

- 0.1.7-rc.2 moves reminder delivery onto the web session-control stack: the schedule plugin now injects `sessionController`, whose own `fileUploads` and `workspaceRegistry` dependencies exist only in the web composition. The terminal composition can never activate it — the `schedule_create` model tools that worked on rc.1 vanish after the update — and upstream's own answer ships `schedule` and `time-context` disabled there. This release drops the rows outright and removes the `/schedule` command, panel, fold, and locale keys with them; historical delivery prompts still replay as ordinary user rows when old sessions are read. Reminders have no terminal channel until upstream decouples delivery from the web stack; the closest available approximation is a model-run background job loop, which does not survive restarts.

## Compatibility and upgrade notes

- The supported host line is `@deepseek-ai/dsh@0.1.7-rc.2`; an older-line host refuses the new bundle at boot by design, so the install commands pin the host version.
- `js-yaml` moves to runtime dependencies (bundled inside the published `lib/`); no action is needed by users.
- npm remains the primary channel; the GitHub Release tarball remains the fallback for restricted networks. A tag push creates the GitHub Release asset but does not run `npm publish`.

Upgrading from 1.5.0:

```sh
npm install -g @deepseek-ai/dsh@0.1.7-rc.2 dsh-code@1.6.0
dsh plugin --profile cli add dsh-code@1.6.0
```

Then `/quit` and start again. `/update` performs the same move in one step once npm carries both versions. A GitHub-tarball installation can be overwritten by the npm command; until npm carries 1.6.0, the updater reports that a tarball install is newer and refuses to downgrade.
