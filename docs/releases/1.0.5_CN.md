# dsh-code 发布说明 - 1.0.5

## 概览

1.0.5 将终端升级到 dsh 0.1.2-rc.1 版本线，并修复了一次外部审计指出的多处问题。问答现在走与审批相同的交互通道，上游预设改名前记录的会话无需迁移即可继续使用，web_fetch 开箱即用（基础 profile 已内置抓取提供方）。/review 在新会话中可直接发起；diff 读取失败会明确报错，不再悄悄缩小审查范围；`deepseek update` 会把全局宿主与 cli profile 锁定在同一条兼容版本线上一起升级。两个终端同时保存主题或状态栏、同时在两个终端输入，都不会再丢掉其中一边的内容。

## 新功能

### /review 无需先发消息

- 新会话不再拒绝 /review。只读权限成为会话的初始权限，审查提示词作为首条消息提交，与手动输入完全一致。这样开始的会话从第一回合起就在状态栏显示只读。

### `deepseek update` 升级所有真正在运行的东西

- 查看模式同时显示四项信息：本启动器运行的版本、将要启动的 @deepseek-ai/dsh 版本、cli profile 实际挂载的版本，以及 npm 上各自的最新版。
- `--apply` 先读取新版 dsh-code 在依赖中声明的 harness 版本线，按这条线安装 @deepseek-ai/dsh，再用同一版本通过 `dsh plugin add` 更新 cli profile——宿主与插件因此始终保持版本兼容。挂载本地代码库的 profile 保持原样，完成后还会读回实际挂载的版本做校验。
- npm 调用改为直接运行 npm 的 JavaScript 入口，Windows 启动壳打印的 Node 弃用警告随之消失。

## 上游对齐：dsh 0.1.2-rc.1

- 问答流接入审批已在使用的 agent 作用域应答通道，与上游交互契约保持一致。
- 上游将 `code` 预设更名为 `ptc`；恢复会话、`--mode` 参数、已配置的默认值与会话内模式切换在每个入口都做了映射，改名前记录的日志继续可用。
- web_fetch 默认开启：基础 profile 内置了匿名抓取提供方，模型侧工具无需任何 key 或配置即可抓取网页。
- 基础 profile 还新增了持久键值存储、会话投影缓存与 DeepSeek LLM API 扩展，随运行时升级一同可用。

## 修复

### diff 读取不再悄悄缩小范围

- 默认对比失败时，/diff 先确认仓库是否只是还没有提交；只有这种情况才退回显示未暂存的改动，并在标题中如实标注。diff 超出大小限制、索引损坏或目录不是仓库都会报错——/review 不会再毫无提示地对着空 diff 或残缺 diff 审查。
- 所有 diff 调用在禁用外部 diff 驱动之外同时禁用文本转换器，仓库无法再趁终端读取 diff 时执行配置的转换程序。

### 并发保存与输入历史互相隔离

- 主题与状态栏的保存改为每次使用独立的临时文件，并在 Windows 短暂锁定目标文件时做少量重试：两个终端同时保存同一个文件不会再丢失其中一次。
- 输入历史改为追加式文件。两个同时运行的终端互相接着写入，而不是各自用启动时读到的快照覆盖整个文件；崩溃最多留下半行，下次启动直接丢弃；陈旧行由启动时的一次原子写入收敛。

## 验证

- 53 个文件共 742 项测试、类型检查、构建与 pack 演练全部通过。
- 三进程并发实验向同一历史文件追加 600 行，零丢失、零交错。
- 已针对升级后的运行时重装 cli profile，help 与配置导出列出全部新增基础行。
