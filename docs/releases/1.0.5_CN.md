# dsh-code 发布说明 - 1.0.5

## 概览

1.0.5 将终端升级到 dsh 0.1.2-rc.1 版本线，并修复了一次完整外部审计在 1.0.4 中发现的全部问题。其中三项在修复前都实际复现过：足够大的暂存变更触发 diff 输出上限后，/review 会被静默缩减到空范围；内置更新命令升级后，实际运行的插件仍停留在旧版本；两个终端保存同一份设置文件时可能丢失其中一次保存。在审计修复之外，/review 现在可以在新会话中直接发起，`deepseek update` 会显示并升级所有真正在运行的版本，输入历史改为追加式文件——并发的终端互相续写，而不是互相覆盖。

对 0.1.2-rc.1 的升级在已有数据上保持保守：会话日志格式未变，1.0.4 及更早版本写入的会话无需转换即可加载；上游将 `code` 预设更名为 `ptc`，所有入口都会自动映射，无需人工迁移。

## 新功能

### /review 无需先发消息

- 新会话不再以「no session yet」拒绝 /review。只读权限成为会话的初始权限，审查提示词作为首条消息提交——与手动输入完全一致。状态栏从第一个回合起就显示只读。
- 全部参数形式可用：`/review`、`/review --staged`、`/review <ref>` 都能在会话建立前从工作目录加载 diff。
- 加载途中发生会话切换时，未完成的 diff 结果会被丢弃，不会落入另一个会话的转录。
- 其余命令的无会话行为也做了同一轮核查：/export、/title、/fork 因为操作对象是会话内容本身，仍需等待会话建立；/copy 会回答「nothing to copy yet」而不是报错。

### `deepseek update` 升级每个实际在运行的版本

- 查看模式一屏显示四项信息：本启动器运行的版本、将要启动的 @deepseek-ai/dsh 版本、cli profile 实际挂载的版本，以及 npm 上各自的最新版。旧的查看模式只打印两个 npm 最新版本号，从不与实际安装情况对比。
- `--apply` 按一个有序流程升级：先读取新版 dsh-code 在依赖中声明的 harness 版本线；按这条线安装 @deepseek-ai/dsh，并安装精确版本的 dsh-code（两者都锁定版本号，安装不受 pnpm 对未指定版本包的首日延迟影响）；用同一版本通过 `dsh plugin add` 更新 cli profile；最后读回实际挂载的版本做校验，不一致时以非零退出并打印修正命令。
- 挂载本地代码库的 profile（`link:`）保持原样——全局包照常升级，开发挂载不受影响。
- 各步骤按顺序执行，首个失败即停止；退出码原样传给 shell。
- npm 自身改为通过 JavaScript 入口运行，Windows `.cmd` 启动壳每次调用打印的 Node 弃用警告随之消失。

## 上游对齐：dsh 0.1.2-rc.1

### 问答与审批共用一条交互通道

- ask_user_question 流程接入审批已在使用的 agent 作用域应答通道，遵循上游 0.1.2-rc.1 的交互契约。一次一题的队列、plan review 的高亮与 Esc 取消行为均保持不变。

### `code` 预设更名为 `ptc`，既有会话继续可用

- 上游在本版本线将内置的 `code` 预设更名为 `ptc`。所有入口都会自动转换：恢复会话（包括已记录的选择与会话头）、`--mode` 参数、已配置的默认值、会话内 /mode 切换。新的选择以当前 id 写入日志，无需任何人工迁移。

### web_fetch 默认开启

- 基础 profile 内置了匿名 HTTP(S) 抓取提供方，模型侧的 web_fetch 工具无需任何 key 或配置即可使用；web_search 维持原有配置。终端自身的 patch 也随之变小——不再需要单独挂载抓取提供方。

### 版本线带来的其他能力

- 基础 profile 新增持久键值存储、按会话的投影缓存（更快的会话列表与标题）、DeepSeek LLM API 扩展和插件包清单；它们随运行时升级一同可用。
- 会话日志格式未变：1.0.4 及更早版本写入的日志无需转换即可加载。
- 一项上游默认值变化值得了解：遥测从禁用改为反馈触发，即只有在你主动运行 /feedback 时才会上传会话记录。设置 `DSH_TELEMETRY_MODE=DISABLED` 可完全退出。


## 修复

### diff 读取不再悄悄缩小范围

- 此前，默认 diff 形式的任何失败都会静默退回只显示未暂存改动。触发 16 MiB 输出上限的暂存变更——复现过的场景——会让 /review 对着空 diff 审查，且没有任何提示。
- 现在回退只适用于没有任何提交的仓库：这一情况会被显式探测，并在结果标题中说明。diff 超出大小限制、索引损坏、目录不是仓库、加载被中止，都会作为错误上报。
- 显式 ref 永不回退：无提交仓库中的 `/diff HEAD` 会像 git 本身一样报错。
- 所有 diff 形式在禁用外部 diff 驱动之外同时禁用文本转换器。此前仓库可以配置 textconv 命令，在终端仅仅读取 diff 时作为副作用执行——这是真实存在的代码执行风险，已在全部路径上封堵。

### 并发保存与输入历史互相隔离

- 主题与状态栏的保存改为每次使用唯一命名的临时文件，并在 Windows 短暂锁定目标文件时做少量重试。此前两个终端保存同一文件会共享一个临时路径，后到者的改名会失败或写入对方的内容——这是被复现的场景。
- 输入历史改为追加式文件。两个同时运行的终端互相续写条目，而不是各自用启动时读到的快照覆盖整个文件。崩溃最多留下半个尾行，下次启动直接丢弃；陈旧行（相邻重复、无法解析的垃圾、超出上限的尾部）由启动时的一次原子写入清理。
- 原子写入本身——唯一临时文件名、重命名替换、短暂锁定重试——抽成了一个共享助手，设置保存与历史压缩共同使用。

## 验证

- 53 个文件共 742 项测试（从 725 项增加）、类型检查、构建与 `pnpm pack --dry-run` 全部通过。
- 三进程并发实验向同一历史文件追加 600 行，零丢失、零交错。
- 已针对升级后的运行时重装 cli profile；`--help` 与 `--dump-config` 列出全部新增基础行。
- 三轮外部审计发现的问题均在本版本修复；已记录的已知缺口（运行器编排层暂无自动化测试架构）维持不变。
