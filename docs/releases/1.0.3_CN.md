# dsh-code 发布说明 - 1.0.3

## 概览

1.0.3 把一次覆盖会话、持久化与控制流的完整外部审计转化为具体修复：删除会话子树前先完成整棵子树的校验，`/mode` 与 `/review` 不再应用到执行期间已切换的会话，用户级设置文件按严格顺序串行写入并以原子方式落盘。终端渲染获得按图形簇计量的测宽引擎、前向计算并遵循中日韩禁则的流式换行，以及每次切换立即重放整份转录的折叠行为。本版本同时新增 `/vscode-keys` 编辑器修复、中继模型推理等级自动继承、思考标记动画与 Node 22/24 CI 矩阵。实时转录折叠对每个事件只需常数级开销，工具密集的长会话不再随转录增长而变慢。

## 新特性

### 编辑器键盘集成

- `/vscode-keys` 一步修复 VS Code 系终端中的 Ctrl+R 冲突。VS Code 在集成终端持有焦点时仍把 Ctrl+R 交给工作台，折叠思考的按键无法到达 TUI。该命令按 `TERM_PROGRAM` 识别宿主编辑器（VS Code 与 Insiders、Cursor、VSCodium、Windsurf；大小写与空白容错），将 `terminal.sendSequence` 放行规则幂等合并进用户级 `keybindings.json`：保留既有 JSONC 注释，规则插在用户规则之前，既有文件在首次写入前备份为 `.dsh-bak`。
- 远程终端会被拒绝执行而不是盲目修改：`VSCODE_IPC_HOOK_CLI` 表明编辑器运行在另一台机器上（SSH、容器、远程开发环境）时，命令会提示该规则需要在本机添加。
- Alt+R 与 Ctrl+R 共用同一终端焦点门控切换折叠，无需任何编辑器配置即可使用；放行规则生效后两个按键同时可用。
- 安装后仅出现一次的启动提示：在 VS Code 系终端内首次启动时以一条通知说明该命令，并在 `~/.dsh/dsh-code/editor-keys.json` 记录；放行规则已存在时不再提示。

### 中继模型的推理等级

- pi-ai provider 设置中手工声明的中继模型，此前除非条目显式写出 `reasoningEfforts`，否则不提供任何推理等级：模型目录按路由键而非模型 id 继承能力，中继路由上手工声明的同 id 模型读取不到目录条目，也不显示 effort 选择器。现在由一个后台流程自动补全声明——存在同 id 的相邻设置声明时逐字复制（保留映射等级名等各接口方言），否则按另一路由的广告等级构造恒等映射，`off` 档位不发送推理参数。
- 写入通过 provider 面板的 `settings.mutate` 通道执行并携带乐观锁 revision，通知会标明来源与获得声明的模型数量。已声明 `reasoningEfforts`（包括显式 `false`）的条目不会被改动。
- 跳过缓存以来源快照与文档 revision 共同为键：外部编辑移除已继承的声明并使 revision 变化后，下一次同步会重新写入，而不是要等到下次启动才恢复。

### 状态指示

- 折叠态思考标记在思考内容单独流出时使用与 `Deep diving` 忙碌行相同的流动蓝色渐变，回答文本开始流出后立即回到静态暗色行，动画不会延迟回答文本的绘制。
- 两份 README 新增状态指示表，说明 Deep diving 行与 Thinking 标记的出现时机，包括忙碌行在 15 秒后开始显示耗时。

## 改进

### 终端单元格测宽

- 专用测宽引擎取代旧的 `codePoint > 0x2e7f ? 2 : 1` 启发式判定：ASCII 快路、`Intl.Segmenter` 图形簇（缺失时回退码点）、以二分查找访问的东亚宽字符与 Emoji_Presentation 合并区间表、VS16 序列计 2 列、组合标记/选择符/连接符计零宽。
- 折行、截断、省略号预算与行核算与终端实际绘制一致。旧判定下漂移的字符类别全部覆盖：✳ ⚠ ❤ 等 text-default emoji 不再占 2 列，谚文 Jamo 与 VS16 序列计数正确，显示文本中的多字符转义字面量按渲染宽度计入预算。

### 流式换行稳定性

- 流式文本从文本起点前向换行并截取尾部行，取代反向扫描、每收到一个分块就重算全部换行点的旧实现——实测此前每个新 token 都会重排整个 live 区。已上屏的行不随 token 追加改变换行，回合结束时不再二次重排。
- 流式期间应用中日韩禁则：收尾标点（，。）等）在满行内悬挂而不是出现在下一行行首，起始标点随后续字符下移；live 区规则与定居渲染器一致，定稿内容保持上屏版式不变。

### 思考折叠行为

- Ctrl/Alt+R 每次切换都通过恰好一次清屏重放整份转录——闲时、流式中、工具执行中、Kitty CSI-u 解码后行为一致。定居条目立即切换到新的折叠状态，不再只有最新条目生效；回合收敛不会追加重放。

### live 区高度预算保护

- 动态区在运行时对照去除界面框架后的高度预算检查：超出屏幕的分配依 answer → reasoning → 已定居行的顺序压缩到预算内，并以一条警告指明超预算的分配形态。过高的 live 区不会再把输入框与状态栏挤出屏幕。

### 长会话性能

- 实时转录折叠改用与持久日志重放同一套可变累加器——工具结果、命令完成、重试与待定行退出均通过 id 索引更新——结构性事件的条目开销与转录长度无关。不可变视图快照按既有通知节流每渲染帧生成一次，而不是每事件生成一次。工具密集的会话不再随转录增长累积平方级的数组复制。

### 子代理活动 feed

- `agents … live · N total` 状态行报告自上次重置以来观察到的去重子会话总数；显示行数仍以 8 行为上限。行满时，新的运行中子代理会替换最旧的已结束行，第 9 个子代理立即获得显示，不再无限等待。
- `/agents` 面板继续合并 live feed 行与会话目录（持久化的子会话），各行完整转录仍可通过 Enter 或 t 打开。

### 持续集成

- CI 在每次推送到 `main` 与每个 pull request 上运行 `pnpm install --frozen-lockfile`、`pnpm test`、`pnpm typecheck`、`pnpm build`，矩阵覆盖 `ubuntu-latest` 与 `windows-latest` × Node 22 与 24，单个任务超时 20 分钟。`engines` 声明（`^22.19 || >=24`）此前没有任何流水线验证。
- `react-devtools-core`——仅被 Ink 的可选 devtools 钩子导入——在构建配置中标记为 external，构建不再为本包从未启用的路径报告未解析的导入。

## 问题修复

### 会话删除

- 此前删除会话子树时校验与删除交错执行：后端没有可删除产物或布局异常时，循环可能在较早的节点已删除后才中止；活跃的子会话被静默跳过，结果却报告成功。现在删除前先对整棵子树完成校验——根或任一成员活跃、id 未知、任一节点没有可定位产物时，在改动任何文件之前整体拒绝；删除按子先父后的顺序执行，只有 I/O 错误可能中断，并按 已删/总数 报告进度。

### 跨会话的命令应用

- `/mode` 在等待 preset 重组完成前捕获了 agent，完成后没有复查：重组期间发生的会话切换会把旧的 preset 写进新会话状态，并把 command 与 skill registry 重新绑定到已释放的 agent。重组现在在串行的 composition 队列内执行，应用前复查 epoch、agent 与 active。
- `/review` 加载 git diff 时未捕获调用会话：大仓库中 diff 可能在用户切换会话之后才完成，将新激活的会话置为只读，并把前一工作区的审查提示发送到该会话。现在命令会捕获会话身份与 cwd，向 `loadGitDiff` 传入 AbortSignal，使切换或退出时直接终止 git 子进程，会话已变时丢弃结果。

### 设置持久化

- `statusline.json` 与 `theme.json` 的保存此前是相互独立、完成顺序不受控的异步写入：连续两次快速修改可能乱序落盘并留下旧快照；退出流程只等待历史记录，修改后立即退出可能丢失设置。现在两个文件的保存共用一条串行写入队列——每次保存先写入同目录临时文件，再以原子改名替换目标文件——退出流程在历史记录写完后继续等待该队列完成。

## 兼容性与升级说明

- dsh-code 1.0.3 要求 `@deepseek-ai/dsh@0.1.1-rc.2`；Harness 依赖仍精确锁定在该版本线。
- 已有 session 无需迁移。升级后首次保存起，用户级设置文件通过原子改名写入；保存期间同目录可能短暂出现 `<name>.tmp` 临时文件。
- 发布首日 pnpm 用户应安装精确版本 `dsh-code@1.0.3`；npm 安装不受 pnpm 发布后 24 小时延迟影响。
