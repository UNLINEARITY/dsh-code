# dsh-code 发布说明 - 1.0.8

## 概览

1.0.8 是针对 1.0.7 启动崩溃的打包修复。1.0.7 默认启用的会话搜索工具依赖 `@deepseek-ai/dsh-tool-session-query`，但本包此前只把它声明为 optional peer：宿主 CLI 不捆绑它，profile 的 `autoInstallPeers: false` 又让 pnpm 不会安装它，于是所有 cli profile 在启动时以 `ERR_MODULE_NOT_FOUND` 崩溃。现在该包作为真实依赖随包发布，默认启用的插件集与 1.0.7 的文档描述完全一致，同类可选能力的启用指引也不再指向无法解析的行。

## 修复

- cli profile 恢复启动：会话搜索包随 bundle 一起发布（钉在同一 0.1.5-rc.2 版本线），从 profile 自身的 node_modules 解析；已用打包产物在模拟的全新 profile 安装中验证。
- 新增套件守卫：任何"默认启用、但其模块既不在 bundle、依赖、也不在宿主安装内"的 patch 行都会被拒绝——1.0.7 崩溃的准确形态，现在会在发布前被拦下，而不是在用户终端里爆发。
- `deepseek update --apply` 不再把升级卡在半途：宿主安装与 dsh-code 挂载仍然致命，但目标版本线上缺少构建的伴生插件会以精确的手动重试命令报告，其余携带继续完成；最终退出码仍如实反映未完成的部分。
- `deepseek` 与 `deepseek setup` 打印的宿主缺失指引现在同时钉住版本线与确切的 bundle 版本（`npm install -g @deepseek-ai/dsh@<版本线> dsh-code@<版本>`），不再指向未钉版本的 `dsh-code`——那可能在新 wrapper 旁挂上更新的 bundle。
- launcher-update 测试把 `fileURLToPath` 的 Windows 渲染写成了唯一期望，自动化套件因此只能在 Windows 上通过；断言现在覆盖两种平台渲染，套件在 macOS 与 Linux 上均为绿色。
- pnpm 12.4+ 对构建脚本未获批准的包拒绝安装；koffi（JSONL 持久化开发路径背后的 FFI 依赖）现已与 esbuild 一同获批。

## 升级须知

- 1.0.7 无法在 cli profile 中启动——请升级到 1.0.8（终端内执行 `/update`，或命令行执行 `deepseek update --apply`）。
- 如果曾用临时方案把该包手动装进 profile，升级后请移除该条目，改由 bundle 依赖提供：`pnpm --dir ~/.dsh/profiles/cli remove @deepseek-ai/dsh-tool-session-query`。

## 文档

- 中英文 README 与 bundle patch 注释现在写明宿主 CLI 捆绑哪些包、哪些需要先装入 profile：PTY 终端工具（`@deepseek-ai/dsh-tool-terminal`）与 LSP 三件套（`@deepseek-ai/dsh-lsp` / `dsh-lsp-stdio` / `dsh-tool-lsp`）；缺少包的情况下启用这些行会以与 1.0.7 相同的方式导致启动失败。
- 安装章节解释了 `npm warn install-scripts` 提示（宿主自带预编译产物，常规平台可忽略），并把排障第一步指向 `deepseek doctor`。

## 验证

- 已在 1.0.7 的打包产物上复现失败解析，并在 1.0.8 tarball 的模拟全新 profile 安装上验证通过；新的 patch 行守卫已确认对 1.0.7 清单会失败。
- typecheck 通过，自动化套件覆盖 62 个文件 877 个测试；一小族对时序敏感的面板测试在全量并行负载下会间歇性抖动、单跑即绿（1.0.7 树上同样存在）。
