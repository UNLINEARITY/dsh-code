# dsh-code 发行说明 - 1.5.0

## 概述

1.5.0 聚焦终端连续性：长对话现在通过物理行视口逐步进入原生 scrollback，真实内容触底后 composer 与状态栏保持稳定。工具卡与 Ctrl+O 减少重复或低价值信息，关闭装饰动画后，运行中的任务也不再显得卡死。本次发布还围绕固定的 Harness 版本线增加显式兼容性、架构与性能门禁；宿主版本仍为 `@deepseek-ai/dsh@0.1.5-rc.2`。

## 终端与转录改进

### 稳定的物理行视口

- 内容较少的对话继续使用终端自然流动。真实转录填满 viewport 后，已落定的物理行单调进入原生 scrollback，同时由有界实时尾窗稳定 composer 与状态栏。
- streaming 收缩、工具落定和超长条目使用真实历史补满 viewport，不插入人为的空白占位。超长条目可以在原生 scrollback 与实时 viewport 之间精确切分。
- 主对话与附加的子代理视图共用同一套行数核算。resize 与 Ctrl+L 从源数据历史重建，无需 alternate screen 即可保留完整重放。
- `/help` 等独占面板在上方保留冻结的真实转录历史，不再清除对话或填充空白。
- 状态栏为终端最后一列预留空间，防止 VS Code 在行宽恰好等于终端宽度时自动换行，并在首 token 到达时产生未计入布局的行、向上顶起底栏。

### 更清晰的工具与历史检查

- 工具预览识别 `file_path` 和具名目标，并能从超大的 write/edit 参数中有界提取路径，使工具卡显示简洁目标，而不是大段 JSON 载荷。
- 展开的 raw、read 与结构化 diff 详情会替代等价摘要。单行命令输出不再重复，也不再错误提示存在隐藏输出；web 补充元数据和错误信息仍完整保留。
- 工具名使用主题强调色，状态符保留语义色；普通思考、参数、摘要和原始输出继续灰显。只有结构化 diff 详情使用主题增删色，原始 Bash 输出不会被启发式猜测为补丁。
- Ctrl+O 从导航与条目计数中排除只有 reasoning、没有最终回答正文的 assistant settlement。持久化事件仍可用于普通转录、思考切换、导出与恢复。

### 必要的活动反馈保持可见

- `/animation off` 现在只关闭装饰性的模型切换 wave/pulse、主题颜色流动与 rainbow burst。
- 输入与 streaming caret、busy chase、Thinking/Deep Diving shimmer 和 `Deep diving...` 耗时计时始终运行，避免活动任务看起来已经卡死。
- 耗时计时拥有独立的低频定时器，即使没有新的转录或 store 事件也会继续更新。

## 可靠性与性能

- 固定 Harness 快照中的每一种会话事件都明确分类为转录可见、由其他终端功能面处理或有意忽略。未知第三方插件事件继续作为兼容性无操作；一方转录事件遗漏 reducer 时则明确失败，不再静默漂移。
- 私有 session-query override 在挂载前验证上游 `_observeStable` 契约，避免上游签名变化后静默失去损坏会话隔离能力。
- `/resume` 的 artifact 检查改用固定 16 个 worker，不再同时打开全部持久会话目录；排序、artifact 缺失回退与取消语义保持不变。
- 运行时 import 循环检查覆盖完整源码图，并强制执行 runner、panel、UI 与 session 的既定依赖边界，同时不把纯类型 import 误判为运行时耦合。
- 新增跨平台性能预算，覆盖 100,000 事件恢复、3,000 条已落定历史重排和 100,000 条历史上的实时 snapshot。限制刻意保留宽裕，只拦截算法级回退，不受普通调度噪声影响。

## 开发与发布保障

- 针对终端布局、工具、平台适配器、结构化提问、权限、模型推理档位、供应商配置、投影兼容性、架构与长会话性能扩充了聚焦行为的回归覆盖。
- CI 继续发布 V8 覆盖率总量用于趋势观察，但质量门禁改由行为回归、类型检查、构建与性能预算承担，不再使用全局覆盖率百分比阈值。
- 标准验证与 `prepublishOnly` 流程现在都包含长会话性能检查。

## 兼容性与升级说明

- Harness peer 版本线没有变化，仍支持 `@deepseek-ai/dsh@0.1.5-rc.2`。
- 没有配置迁移，也没有正式 package entry point 变化。
- 行为变化：`/animation off` 现在是装饰动态偏好，而不是冻结全部定时器；必要活动指示与 shimmer 会继续运行。
- 行为变化：Ctrl+O 不再把 reasoning-only assistant settlement 计为独立可检查回复；不会删除任何持久会话数据。
- npm 仍是主要渠道；GitHub Release tarball 仍作为受限网络的备用方式。推送 tag 会创建 GitHub Release 资产，但不会执行 `npm publish`。

从 1.4.0 升级：

```sh
npm install -g dsh-code@1.5.0
dsh plugin --profile cli add dsh-code@1.5.0
```

然后执行 `/quit` 并重新启动。从 GitHub tarball 安装的版本可以直接被 npm 命令覆盖。在 npm 尚未发布 1.5.0 时，更新器会提示 1.5.0 tarball 安装比 npm 新，并拒绝降级。
