# dsh-code Release Notes - 1.0.5

## Overview

1.0.5 upgrades the terminal to the dsh 0.1.2-rc.1 line and fixes every issue found in a full external audit of the 1.0.4 release. Three of the audit findings were confirmed with reproductions before fixing: a staged change large enough to hit the diff output limit silently reduced /review to an empty scope, the built-in update command left the actually-running plugin on its old version, and two terminals saving the same settings file could lose one of the saves. Alongside the audit work, /review now starts directly in a fresh session, `deepseek update` shows and upgrades every version that actually runs, and input history becomes an append-only file that concurrent terminals extend instead of overwrite.

The alignment to 0.1.2-rc.1 is deliberately conservative for existing data: the session log format is unchanged, sessions written by 1.0.4 and earlier load without conversion, and the upstream rename of the `code` preset to `ptc` is bridged automatically at every entry point.

## New features

### /review works before the first message

- A fresh session no longer rejects /review with "no session yet". The read-only permission becomes the session's starting permission, and the review prompt is submitted as its first message — exactly as if it had been typed. The status line shows read-only from the very first turn.
- All argument forms work: plain `/review`, `/review --staged`, and `/review <ref>` each load the diff from the working directory before any session exists.
- A diff load that outlives a session switch started while it was in flight is dropped instead of landing in the wrong session's transcript.
- The remaining no-session guards were audited at the same time: /export, /title, and /fork still wait for a session because they operate on its content, and /copy answers "nothing to copy yet" instead of failing.

### `deepseek update` upgrades everything that actually runs

- The check mode shows four facts in one screen: the version this launcher runs, the version of @deepseek-ai/dsh it would boot, the version the cli profile actually mounts, and the latest of each on npm. The old check only printed the two npm latest versions and never compared them with what is installed.
- `--apply` upgrades in one ordered sequence: read the harness line the new dsh-code release declares in its dependencies, install @deepseek-ai/dsh at exactly that line and dsh-code at exactly its published version (both pinned, so the install is immune to pnpm's first-day delay for unpinned packages), update the cli profile through `dsh plugin add` with the same version, then read back the mounted version and verify it. A mismatch exits non-zero and prints the exact command to fix it.
- A profile that mounts a local checkout (`link:`) is left untouched — the global packages upgrade, the development mount stays as-is.
- The steps run in order and stop at the first failure; each exit code reaches your shell unchanged.
- npm itself now runs through its JavaScript entrypoint, which removes the Node deprecation warning the Windows `.cmd` shim used to print on every call.

## Upstream alignment: dsh 0.1.2-rc.1

### Questions and approvals share one interaction channel

- The ask_user_question flow joins the agent-scoped answer channel that approvals already use, following the upstream contract for 0.1.2-rc.1. The one-question-at-a-time queue, plan-review highlighting, and Esc-to-cancel behavior are unchanged.

### The `code` preset became `ptc`; existing sessions keep working

- Upstream renamed the shipped `code` preset to `ptc` in this line. Every entry point translates automatically: resumed sessions (both the logged selection and the session header), `--mode` arguments, the configured default, and in-session /mode switching. New selections are written under their current ids, so nothing needs manual migration.

### web_fetch on by default

- The base profile now bundles an anonymous HTTP(S) fetch provider and enables the model-facing web_fetch tool without any key or setup; web_search keeps its existing configuration. The terminal's own patch got smaller at the same time, since it no longer needs to mount the fetch provider itself.

### What the runtime line brings

- The base profile gains durable key-value storage, a per-session projection cache (faster session lists and titles), DeepSeek LLM API extensions, and a plugin package inventory; they become available together with the runtime upgrade.
- Session log format is unchanged: logs written by 1.0.4 and earlier load without conversion.
- One upstream default changed and is worth knowing: telemetry moved from disabled to feedback-gated, meaning session records upload only when you explicitly run /feedback. Set `DSH_TELEMETRY_MODE=DISABLED` to opt out entirely.

## Fixes

### Diff reading can no longer quietly shrink its scope

- Previously, any failure of the default diff form silently fell back to showing only unstaged changes. A staged change past the 16 MiB output limit — the reproduced case — made /review run against an empty diff without a single warning.
- Now the fallback applies only to a repository without commits, which is probed explicitly and stated in the result title. An oversized diff, a broken index, a directory that is not a repository, or an aborted load is reported as an error.
- Explicit refs never fall back: `/diff HEAD` in a commit-less repository errors exactly as git does.
- Every diff form disables text converters alongside external diff drivers. Before, a repository could configure a textconv command that would execute as a side effect of merely reading its diff — a real code-execution vector, closed on every path.

### Concurrent saves and input history are isolated

- Theme and status-line saves write through a temp file whose name is unique to each save, with a short retry when Windows briefly locks the target. Previously two terminals saving the same file shared one temp path, and the loser's rename failed or landed the other's content — the reproduced case.
- Input history is now an append-only file. Two terminals running at the same time add entries after each other instead of each overwriting the file with the snapshot it read at startup. A crash can at worst leave a half-written last line, which the next startup drops; stale lines (adjacent duplicates, unparsable garbage, an over-cap tail) are rewritten once at startup through the same atomic write.
- The atomic write itself — unique temp name, rename into place, retry on transient locks — is now one shared helper used by settings saves and history compaction alike.

## Verification

- 742 tests across 53 files (up from 725), typecheck, build, and `pnpm pack --dry-run` all pass.
- A three-process experiment appended 600 lines to one history file with no loss and no interleaved lines.
- The cli profile was reinstalled against the upgraded runtime; `--help` and `--dump-config` list every new base row.
- Every finding from three rounds of external audit is addressed in this release; the documented known gaps (no automated harness for the runner's orchestration layer) carry over unchanged.
