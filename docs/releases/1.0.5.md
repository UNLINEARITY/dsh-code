# dsh-code Release Notes - 1.0.5

## Overview

1.0.5 upgrades the terminal to the dsh 0.1.2-rc.1 line and fixes every issue found in a full external audit. Questions now use the same interaction channel as approvals, sessions recorded before the upstream preset rename keep working without migration, and web_fetch works out of the box because the base profile now ships the fetch provider. /review starts directly in a fresh session, a diff that fails to load is reported instead of quietly shrinking what gets reviewed, and `deepseek update` upgrades the global launcher and the cli profile together on one pinned version line. Saving the theme or the status line from two terminals at once, and typing in two terminals at once, no longer lose one side's work.

## New features

### /review works before the first message

- A fresh session no longer rejects /review. The read-only permission becomes the session's starting permission and the review prompt is submitted as its first message, exactly like a typed prompt. Sessions started this way show read-only in the status line from the very first turn.

### `deepseek update` upgrades everything that actually runs

- The check mode shows the whole picture at once: the version this launcher runs, the version of @deepseek-ai/dsh it would boot, the version the cli profile actually mounts, and the latest of each on npm.
- `--apply` reads the harness line the new dsh-code release declares in its dependencies and installs @deepseek-ai/dsh pinned to that line, then updates the cli profile through `dsh plugin add` with the same pinned version — the launcher can never move ahead of the plugin it must boot. A profile that mounts a local checkout keeps its mount untouched, and the mounted version is read back and verified at the end.
- npm calls now run npm's JavaScript entrypoint directly, which removes the Node deprecation warning the Windows launcher shim used to print.

## Upstream alignment: dsh 0.1.2-rc.1

- The question flow joins the agent-scoped answer channel that approvals already use, matching the upstream interaction contract.
- The upstream rename of the `code` preset to `ptc` is bridged at every entry point — resumed sessions, `--mode` arguments, configured defaults, and in-session mode switching — so logs recorded before the rename keep loading.
- web_fetch is enabled by default: the base profile now bundles the anonymous fetch provider, and the model-facing tool exposes it without any key or setup.
- The base profile also gains durable key-value storage, a session projection cache, and DeepSeek LLM API extensions; they become available together with the runtime upgrade.

## Fixes

### Diff reading can no longer quietly shrink its scope

- When the default comparison fails, /diff first checks whether the repository simply has no commits yet; only that case falls back to showing unstaged changes, with the title saying so. An oversized diff, a broken index, or a directory that is not a repository is reported as an error — /review can no longer run against an empty or partial diff without a warning.
- Every diff invocation now disables text converters alongside external diff drivers, so a repository can no longer execute a configured converter while the terminal is merely reading its diff.

### Concurrent saves and input history are isolated

- Theme and status-line saves write through a unique temp file per save, with a short retry when Windows briefly locks the target: two terminals saving the same file no longer lose one of the saves.
- Input history is now an append-only file. Two terminals running at the same time add entries after each other instead of each overwriting the file with the snapshot it read at startup; a crash can at worst leave a half-written last line, which the next startup drops; and stale lines are compacted once at startup through the same atomic write.

## Verification

- 742 tests across 53 files, typecheck, build, and a pack dry run all pass.
- A three-process experiment appended 600 lines to one history file with no loss and no interleaving.
- The cli profile was reinstalled against the upgraded runtime; help and config dumps list every new base row.
