# dsh-code Release Notes - 1.0.3

## Overview

1.0.3 converts a full external audit of the session, persistence, and control-flow layer into concrete fixes: session-subtree deletion is preflighted as a whole, `/mode` and `/review` can no longer apply to a session that changed while they were running, and user-level settings files persist through one serialized, crash-atomic chain. Terminal rendering gains a grapheme-accurate width engine, forward-computed streaming wraps with CJK line-breaking rules, and a fold that replays the whole transcript immediately on every toggle. The release also adds the `/vscode-keys` editor repair, automatic reasoning-level inheritance for relay models, an animated thinking marker, and a Node 22/24 CI matrix. Live transcript folding now costs constant work per event, so long tool-heavy sessions no longer slow down as they grow.

## New features

### Editor keyboard integration

- `/vscode-keys` repairs the Ctrl+R conflict in VS Code-family terminals in one step. VS Code routes Ctrl+R to the workbench even while the integrated terminal holds focus, so the reasoning-fold key never reached the TUI. The command detects the hosting editor from `TERM_PROGRAM` (VS Code and Insiders, Cursor, VSCodium, Windsurf; matched case- and whitespace-tolerantly) and idempotently merges a `terminal.sendSequence` passthrough rule into the user-level `keybindings.json`: existing JSONC comments survive, the rule is inserted ahead of user rules, and an existing file is backed up once as `.dsh-bak` before the first write.
- Remote terminals are refused rather than patched blindly: when `VSCODE_IPC_HOOK_CLI` indicates the editor runs on another machine (SSH, containers, remote-development setups), the command reports that the rule must be added on the local machine.
- Alt+R joins Ctrl+R as a fold toggle under the same terminal-focus gate, so folding works with zero editor configuration; Ctrl+R takes over once the passthrough rule exists.
- The repair is advertised once per install: a startup notice inside a VS Code-family terminal names the command and records itself under `~/.dsh/dsh-code/editor-keys.json`; an already-present passthrough rule suppresses the notice.

### Reasoning levels for relay models

- Relay models declared in pi-ai provider settings previously served no reasoning levels unless their entry spelled out `reasoningEfforts`: the model catalog inherits capabilities by route key, not by model id, so a hand-declared model on a relay route read nothing from the catalog entry of the same id and offered no effort picker. A background pass now materializes the declaration — verbatim from a sibling settings declaration for the same model id when one exists (preserving dialect wire spellings such as mapped level names), otherwise an identity level map built from another route's advertised efforts, where `off` sends no reasoning parameter.
- Writes ride the provider panel's `settings.mutate` path under optimistic revisions, with a notice naming the source and the number of models that gained declarations. An entry that already declares `reasoningEfforts` — including an explicit `false` — is never touched.
- The skip cache is keyed by the source snapshot plus the document revision, so an external edit that removes an inherited declaration and bumps the revision is re-applied on the next sync instead of being ignored until the next start.

### Status indicators

- The collapsed thinking marker animates with the same moving blue gradient as the `Deep diving` busy line while reasoning streams on its own, and falls back to the static dim row as soon as answer text starts flowing, so the animation never competes with the answer paint.
- Both READMEs gained a status-indicator table documenting when the Deep diving line and the Thinking marker appear, including the 15-second threshold before the elapsed clock joins the busy line.

## Improvements

### Terminal cell-width measurement

- A dedicated width engine replaces the `codePoint > 0x2e7f ? 2 : 1` heuristic: an ASCII fast path, `Intl.Segmenter` grapheme clusters with a code-point fallback, a merged East-Asian Wide and Emoji_Presentation range table searched by binary search, two cells for VS16 sequences, and zero width for combining marks, selectors, and joiners.
- Wraps, truncations, ellipsis budgets, and row accounting now match what terminals draw. The classes that drifted under the heuristic are covered: text-default emoji such as ✳ ⚠ ❤ no longer reserve two cells, Hangul Jamo and VS16 sequences count correctly, and multi-character escape literals inside displayed text are budgeted by their rendered width.

### Streaming wrap stability

- Streaming text wraps forward from the text start and slices the tail rows, instead of scanning backward and recomputing every wrap point per chunk — probe measurements previously showed each new token re-arranging the whole live block. Rows already on screen keep their wrapping as tokens arrive, and the turn-end flush no longer reflows the block.
- CJK line-breaking rules apply while streaming: closing punctuation (，。）等) overhangs within the filled row instead of starting the next one, opening punctuation moves down with the following character, and the live rules match the settled renderer, so the finalized block keeps its on-screen layout.

### Reasoning fold behavior

- Ctrl/Alt+R replays the entire transcript on every toggle — idle, mid-stream, during a running tool, or after a Kitty CSI-u decode — through exactly one screen clear. Settled entries switch to the new fold state immediately instead of only the latest entry, and turn settlement adds no extra replay.

### Live region budget guard

- The dynamic region is checked against the post-chrome height budget at runtime: an allocation that would overflow is clamped in answer, then reasoning, then settled-row order, with a single warning naming the offending shape. An oversized live block can no longer push the composer and status line off screen.

### Long-session performance

- Live transcript folding runs on the same mutable accumulator the persisted-log replay uses — id-indexed updates for tool results, command completions, retries, and pending-row retirement — so a structural event costs constant entry work regardless of transcript length. Immutable view snapshots are produced once per rendered frame under the existing notification throttle instead of once per event. Tool-heavy sessions no longer accumulate quadratic array copying as the transcript grows.

### Subagent activity feed

- The `agents … live · N total` status line reports the count of distinct child sessions observed since the last reset; the row display stays capped at eight. When the cap is full, a new running child evicts the oldest finished row, so a ninth agent becomes visible instead of waiting behind completed work.
- `/agents` continues to merge live feed rows with the session directory (persisted children), and each row's full transcript stays reachable through Enter or t.

### Continuous integration

- CI runs `pnpm install --frozen-lockfile`, `pnpm test`, `pnpm typecheck`, and `pnpm build` on every push to `main` and on pull requests, across an `ubuntu-latest` and `windows-latest` matrix on Node 22 and 24 with a 20-minute job timeout. The `engines` range (`^22.19 || >=24`) was previously unverified by any pipeline.
- `react-devtools-core` — imported by Ink only for its optional devtools hook — is marked external in the build configuration, so builds no longer report an unresolved import for a path this package never enables.

## Bug fixes

### Session deletion

- Deleting a session subtree previously interleaved validation with removal: a backend without a deletable artifact or an unexpected layout aborted mid-loop after earlier nodes were already gone, and a live child was skipped silently while the result still reported success. Deletion now plans the whole subtree first — refusing when the root or any member is live, when an id is unknown, or when any node has no locatable artifact — before touching a single file; removal runs children-first, and only an I/O error can stop it short, reported with removed-of-total counts.

### Cross-session command application

- `/mode` captured the agent before awaiting its preset recomposition but never revalidated afterwards, so a session switch that landed during the recomposition wrote the old preset into the new session's state and rebound the command and skill registries to a disposed agent. The recomposition now runs inside the serialized composition queue and rechecks epoch, agent, and active before applying.
- `/review` loaded its git diff without capturing the calling session: on a large repository the diff could complete after the user had switched, flipping the newly active session read-only and sending the previous workspace's review prompt into it. The command now captures the session identity and cwd, passes an AbortSignal into `loadGitDiff` so a switch or quit terminates the git subprocess, and discards the result when the session changed.

### Settings persistence

- `statusline.json` and `theme.json` saves floated on untracked promises: two rapid edits could land out of order and leave the older snapshot on disk, and quit waited only for the recall history, so a setting changed right before exit could be lost. Both files now persist through one shared write chain — each save staged through a sibling temp file and renamed into place — and the quit sequence waits for the chain after the history flush.

## Compatibility and upgrade notes

- dsh-code 1.0.3 requires `@deepseek-ai/dsh@0.1.1-rc.2`; the Harness dependency line remains pinned to that release.
- Existing sessions require no migration. User-level settings files are rewritten through atomic renames from the first save after upgrading; a `<name>.tmp` sibling may appear transiently next to them during a save.
- On release day, pnpm users should install the exact package version `dsh-code@1.0.3`; npm installation is not affected by pnpm's 24-hour release delay.
