# dsh-code 发布说明 - 1.0.6

## 概述

1.0.6 将终端升级到 dsh 0.1.5-rc.1 版本线，并在读取端适配会话日志格式 v3。旧会话完全不受影响：早期版本写入的日志经内存迁移加载，磁盘上的文件保持逐字节不变。在版本线对齐之外，终端新增文件附件、覆盖斜杠与提及菜单的模糊补全、/model 页面的供应商配置诊断、首条消息之前即可使用的技能列表，以及一条命令即可升级整个 cli profile 的更新方式。针对对齐工作的对抗式审计修复了一处功能损坏（/fork）与若干交互缺陷；新宿主启动期集中注册命令所引发的 React 更新循环也已修复。

## 新特性

### 图片之外的文件附件

- 终端粘贴与拖拽现在按类型分流：图片仍作为图片块发送，其余路径形态的条目（盘符、UNC、`file://` 或分隔符后带后缀的文件名）成为按原样发送的持久文件附件。散文、斜杠命令与裸词保持纯文本；混合粘贴的内容不会被只附加其中一部分。
- 上限明确：单文件 8 MiB 以内，每条消息最多 8 个文件。
- composer 对文件草稿采用与图片草稿一致的管理方式：可见的 `[file: 名 · 字节]` 标记、删除跟随标记、Ctrl+C 一并清空，提交时两类并行准备。
- 转录、Ctrl+O 详情与 /export 在已定居行和排队行上将文件标签与图片标签并列显示。
- 命令不能携带附件：带附件提交斜杠行时终端会明确提示，该行仍按既有行为作为提示词发给模型，区别在于现在有清楚的提示。

### 模糊补全与首条消息前的技能列表

- `/` 与 `@` 菜单按大小写不敏感的有序子序列匹配，前缀命中优先——采用与 Web 客户端相同的排序规则。`/md` 找到 `/mode`；`@pk` 把 `package.json` 提到最前。
- 提及菜单只调整顺序、不丢弃行：命中行升到前面之后，上游仍返回的其余行按原顺序跟随。
- 技能从第一屏起就出现在 `/` 菜单中，无需先建立会话：技能注册表启动时读取工作目录的全局层，首个会话建立后升级为会话作用域视图。模型侧的技能调用不变——仍随所选预设按会话挂载。
- registry 命令仍随首个会话到达（宿主列出接口要求 agent）；内置本地命令在此期间覆盖常用操作。

### 供应商配置诊断

- 配置损坏的供应商不再从 /model 消失：适配器的错误随目录行传递，列表将其追加到行尾，统一配置页在标题下以警示色展示；供应商保留在列表中，可直接修复。

### 当前系统提示可见

- /export 在会话头与首条记录之间输出当前生效的系统提示折叠块，persona 变更从此可以核对。

### /agents 新增持久目录行

- 会话派生的每个子代理可显示为空闲行，携带目录事件记录的标签与模式，与既有实时活动行并列。

### `deepseek update` 一并升级整个 profile

- 经 `dsh plugin add` 装进 cli profile 的插件，现在在同一次 `update --apply` 中升级到新版本线——一条命令同时升级宿主、dsh-code 与全部附加插件。@deepseek-ai 作用域之外的社区包不会被改动。
- 计划版本线低于已安装宿主时，更新器拒绝降级并打印手动命令，不再静默降级环境。

## 上游对齐：dsh 0.1.5-rc.1

### 读取端适配会话日志格式 v3

- 早期版本写入的日志在读取时经内存迁移加载；磁盘文件从不重写，一个会话目录中可并存多个不可变代际。
- 实时打字与持久日志分离：转录存储现在通过折叠进程内的 assistant-stream 帧呈现流式输出，落盘的回复从内嵌的流记录还原文本与首 token 计时。重放会话得到与实时运行相同的视图和延迟统计。
- 系统提示成为一等 surface 消息；上下文估算随之调整，并在压缩后保持准确：任意 surface 替换都会移除其覆盖区间内的系统节点。
- `/fork` 通过新契约字段记录谱系；旧写法已被发布内核明确拒绝。

### 随版本线到达的宿主能力

- 模型目录新增 DeepSeek-V41-Flash 并成为新会话默认；模型发现支持 anthropic-messages 协议列举并理解更多网关字段；损坏的供应商目录降级为可见诊断而非消失。
- 代理环境变量到达子进程；MCP 工具分页检测 continuation 游标循环；Windows 上的工具中断经 Job Objects 立即终止进程组。
- 模型切换现在向转录追加一条持久通知行。
- 内核的按会话投影缓存加速会话列表冷读。

## 修复

- 在新宿主上打开终端、未输入即出现 "Maximum update depth exceeded" 警告：命令注册表的通知在每条事件中都向 React 提供新创建的数组，连续触发嵌套更新。观察器现在在目录未变时保持原数组引用并合并通知；skills 的错误路径与子代理目录折叠遵循同一规则。
- 排队切换会话落地时，切换前准备的附件提交可能投递进新会话；投递现在携带发起会话的标识，运行层丢弃过期投递。
- 压缩摘要可能使系统提示估算继续计入已被移除的节点；估算现在只跟随保留的合成结果。
- 迟到的子代理目录事件可能把已结束的子代理行回退为空闲状态，并使其始终留在面板中无法替换；目录事件现在保持行的当前状态，面板行数已满时改为替换最旧的非运行行，新子代理保持可见。
- /delete 将不可读目录计为失败，不再静默报成功。
- 统一配置页的诊断行计入面板高度预算。
- 启动器的线序比较、宿主版本探测与插件携带步骤均有测试覆盖；双语上游审计记录完整对齐。

## 验证

- 54 个文件共 788 项自动化测试、typecheck、build、peers 检查与 `pnpm pack --dry-run` 全部通过；每个阶段后移除并重装 cli profile，`--help` 与 `--dump-config` 均验证。
- 早期版本写入的会话经内存迁移加载且磁盘文件不变；流式、重试统计与恢复视图与实时运行一致。
