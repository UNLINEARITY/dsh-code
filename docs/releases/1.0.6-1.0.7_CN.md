# dsh-code 发布说明 - 1.0.6 → 1.0.7

## 概述

1.0.6 与 1.0.7 将终端整体升级到 dsh `0.1.5-rc.2` 版本线：读取端适配会话日志格式 v3，旧会话通过内存迁移加载，磁盘文件保持逐字节不变；升级只需一条命令——终端内的 `/update` 或命令行的 `deepseek update --apply`——即可同时升级 dsh-code、全局宿主与 cli profile 中的全部插件；官方插件集默认装配。使用体验同步改进：新增文件附件与模糊补全，Shift+Tab 增加 plan 档位，斜杠指令与提示词共用同一份输入历史，中文输入法的组合窗与候选窗跟随输入光标，终端标签随会话名称显示并在获得焦点时自动恢复。

## 新特性

### 一条命令完成对齐升级

- 终端内的 `/update` 与命令行的 `deepseek update --apply` 都能在一次操作中同时升级 dsh-code、全局宿主与 cli profile 已安装的插件，保持三者版本线一致；@deepseek-ai 作用域之外的社区包不受影响。
- 当计划升级的版本线低于已安装的宿主时，更新器会拒绝降级，并输出手动升级命令，不再静默降级。

### 官方插件集默认装配

- 日程提醒、时间上下文（30 秒快照）与会话检索索引默认启用；会话检索附带只读的会话工具，索引在首次搜索时才建立。
- PTY 与各平台终端工具、MCP 服务器、hooks 桥接、LSP 以文档化模板提供，按需启用。
- 各面板的搜索与过滤行为保持一致，/mode 等列表面板的体验不再各不相同。

### 文件附件

- 终端粘贴与拖拽按类型分流：图片仍作为图片块发送；其他路径形式的条目（盘符、UNC、`file://`，或带分隔符与扩展名的文件名）作为文件附件原样发送。普通文本、斜杠命令与单个词保持纯文本，混合粘贴的内容也不会被拆散。
- 限制明确：单个文件不超过 8 MiB，每条消息最多 8 个文件。
- 文件草稿与图片草稿的管理方式一致：显示 `[file: 名字 · 字节数]` 标记，删除时跟随标记，Ctrl+C 一并清空，提交时两类附件并行处理。
- 会话记录、Ctrl+O 详情与 /export 在历史行与排队行上将文件标签与图片标签并列显示。
- 命令不能携带附件：带附件提交斜杠行时会明确提示，该行仍作为提示词发送给模型。

### 模糊补全与首条消息前的技能列表

- `/` 与 `@` 菜单按大小写不敏感的有序子序列匹配，前缀命中优先，排序规则与 Web 客户端一致；`/md` 可以找到 `/mode`，`@pk` 会把 `package.json` 排到最前。
- 提及菜单只调整顺序、不丢弃结果：命中的行排到前面，其余行按原顺序跟随。
- 技能从第一屏起就出现在 `/` 菜单中，无需先建立会话；registry 命令随首个会话到达，在此之前内置命令覆盖常用操作。

### Shift+Tab 新增 plan 档位

- 循环顺序为 workspace-write → danger-full-access → read-only → plan。进入 plan 时在 read-only 预设之上提交上游 /plan 命令，plan 模式在工具层强制生效，而不只是提示层约束。
- 在首个会话建立之前，该选择会先保留，并随开场消息一并生效；状态栏用专用的绿色 plan 标识显示当前档位，第二行保留蓝色 ⧉ plan 标记。

### 终端标签标题

- 标签默认显示 deepseek，会话命名后跟随会话名称；退出终端后恢复宿主默认标签。
- 标题经两条通道写入（OSC 0 序列与 Windows 进程标题）：Windows Terminal 无需配置即可生效；在 VS Code 集成终端中，TUI 会在首次启动时自动写入一次 `terminal.integrated.tabs.title: \${sequence}` 设置（已有自定义值不会被覆盖，原文件保留 .dsh-backup 备份）。
- 切换回终端窗口时自动恢复标签：与该控制台共享的后台进程（例如测试运行器）改写标题后，重新获得焦点即恢复。

### 共享召回历史

- 输入的斜杠指令与提示词共用同一份历史：Up/Down 与 /history 面板同时展示两者，跨会话保留，相邻重复自动合并，上限仍为 100 条。
- 对于未被编辑的召回条目，光标位于行首或行尾时，方向键都可以直接切换历史条目；光标移到文本中间则进入普通编辑，多行内容先在行间移动光标，到达边缘后再切换历史；召回条目与恢复的草稿光标都停留在行尾。

### 中文输入法光标锚定

- 输入法的组合窗与候选窗跟随 composer 光标，中文输入不再出现在屏幕边缘或遮挡状态栏；召回出的斜杠指令也不会再被补全菜单占用方向键。

### 供应商配置诊断

- 配置损坏的供应商不再从 /model 中消失：错误信息随目录行显示，统一配置页在标题下方以警示色标出；供应商保留在列表中，可以直接修复。

### 查看当前系统提示

- /export 在会话信息头与首条记录之间输出当前生效的系统提示折叠块，persona 的变更从此可以核对。

### /agents 持久目录行

- 会话派生的每个子代理都可以以独立行的形式显示，携带目录事件记录的标签与模式，与实时活动行并列。

## 上游对齐：dsh 0.1.5-rc.2

### 读取端适配会话日志格式 v3

- 早期版本写入的日志在读取时通过内存迁移加载；磁盘文件从不重写，同一会话目录可以并存多个不可变的代际文件。
- 实时输入与持久日志分离：转录通过折叠进程内的 assistant-stream 帧呈现流式输出，落盘的回复从内嵌的流记录还原文本与首 token 计时；回放的会话与实时运行具有相同的视图和延迟统计。
- 系统提示成为一等 surface 消息；上下文估算随之调整，并在压缩后保持准确。
- `/fork` 通过新的契约字段记录谱系；旧写法会被发布版内核明确拒绝。

### 随版本线到达的宿主能力

- 模型目录新增 DeepSeek-V41-Flash 并作为新会话默认；模型发现支持 anthropic-messages 协议列举，并理解更多网关字段；损坏的供应商目录降级为可见的诊断信息，而不是直接消失。
- 代理环境变量会传递到子进程；MCP 工具的分页结果正确识别 continuation 游标；Windows 上的工具中断通过 Job Objects 立即终止进程组。
- 模型切换向会话记录追加一条持久通知行；内核的按会话派生视图缓存加快会话列表的冷读取。

## 修复

- 在新宿主上打开终端后，未输入任何内容即出现 "Maximum update depth exceeded" 警告：命令注册表在目录没有变化时也生成了新的列表对象，触发 React 连锁更新；现在目录未变化时复用原对象并合并通知，skills 的错误路径与子代理目录折叠遵循同一规则。
- 排队切换会话落地时，切换前准备好的附件提交可能进入新会话；提交现在携带发起会话的标识，运行层丢弃过期的提交。
- 压缩摘要可能让系统提示估算继续计入已移除的节点；估算现在只跟随保留的合成结果。
- 迟到的子代理目录事件可能把已结束的子代理行回退为空闲状态并使其无法替换；目录事件现在保持行的当前状态，面板行数已满时替换最旧的非运行行。
- 会话搜索跳过无法解析的存量会话：单个损坏会话不再导致全部查询失败，被跳过的会话记录警告并在后续搜索中自动重试；等价的上游补丁随 docs/upstream 提供。
- 版本较旧的本地开发副本会拒绝与较新的全局宿主配对，避免以不一致的版本组合静默运行。
- /delete 将不可读目录计为失败，不再静默报成功；统一配置页的诊断行计入面板高度预算。
