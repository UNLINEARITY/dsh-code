# dsh-code 发行说明 - 1.6.0

## 概述

1.6.0 将终端迁移到上游 `@deepseek-ai/dsh@0.1.7-rc.2` 线，并把本版的新事实变成终端功能面。每个顶层回合结束展示 git 级别的变更文件摘要（`⟳ 3 changed files · +42 −7`，附逐文件增删行数），动态工具加载渲染一行暗色标记（`⚙ +web-search · −lsp`），上下文分段条新增图片段并遵循图片 offload。跨会话搜索不再阻塞：引擎跑在 dsh 主目录下的持久索引上，冷读与标题富化各带明确限界。0.1.7 的设置迁移获得端到端保护——滞留的供应商/模型配置在启动时被检测并经宿主自身的设置管道重新导入；提醒功能则诚实地离开终端，因为其 rc.2 投递栈只存在于 web 组合。

## 对齐上游 0.1.7-rc.2

- 全部 Harness 依赖升级到 0.1.7-rc.2，支持的宿主线随之移动：两份 README 的安装命令显式钉住 `@deepseek-ai/dsh@0.1.7-rc.2`，因为 npm 上宿主的 `latest` 发布标签仍指向旧线。`/update` 从本版本自身的 peers 推导宿主线，启动器、bundle 与 profile 插件始终作为一个对齐的整体移动。
- 上游把 `dsh-llm-deepseek` 改名为 `dsh-llm-deepseek-api-key`，并在其旁新增 `llm-deepseek-account` 通道；用户层的行名经 base 组合自动跟随。
- 已退役的 agent-presets 与 code-runtime 包由 preset registry 及 dsh-base 自带的 ptc 运行时取代；bundle patch 以 `presets/` 目录下按序生效的 patch 文件承载四个预设声明。
- 会话转写折叠改读 v4 格式：工具结果采用扁平化的 tool 角色消息，生产者来源按各自 kind 匹配而不再依赖已退役的 plugin 包装，developer-message、image-offload、workspace-changes 三个新事件获得明确处置，fork 的任务结束时渲染标记。旧格式会话日志在读取时由内核自动迁移（v3→v4），磁盘上的原始文件保持不变；旧会话与启动参数中记录的 `code` 预设自动映射到改名后的 `ptc`。
- jobs 行改用重写后的服务（按会话 id 列出），子代理目录兼容新增的 unknown 模式。

## 回合级可见性（新投影）

- 每个顶层回合结束展示变更文件行——`⟳ N changed files · +a −d`，其后最多列出十二个文件的逐文件增删行数——数据来自宿主自带的 `workspace-changes` 记录器（回合首尾的工作树 git 快照，外加 git 覆盖不到路径的文件工具捕获；无 git 环境下列出文件工具编辑）。该行在实时摘要存续期间取代 diff 来源的 `⎄ files` 行，恢复会话后回退到持久行；Ctrl+O 可检查增强详情。
- 动态工具加载按 developer 消息渲染一行暗色标记（`⚙ +web-search · −lsp`）；纯文本 developer 消息保持折叠。
- 上下文分段条新增按内在像素估价的 `images` 段，`image/offload` 决策精确减除，长上下文图片回缩后条形图与模型视角一致。估价只驱动比例；计费仍读取宿主 token meter。

## 跨会话搜索解锁

- 搜索引擎此前跑在内存索引上，每次启动的首搜都要重新解压并解码全部持久会话语料——几百个 zstd 日志就是分钟级。索引现在以 SQLite 数据库持久化于 dsh 主目录（owner-only、自动建目录）：一次完整构建，此后增量协调。
- 每个持久会话的冷读带三十秒限界；真正截断的 zstd 帧会让上游流式解码器无错永久等待，而一个这样的日志能卡死所有搜索。超时的读记为一个带警告的跳过源——语料其余部分照常入库。
- 标题富化带八秒预算：超时的结果行保留短 id 标签与匹配片段，面板不再被重型日志的标题折叠阻塞。
- 在 358 会话语料上端到端验证：冷启动数秒内渲染结果；从打包 tarball 全新安装的 profile，击键后 3.4 秒渲染首次搜索结果。

## 终端可靠性

- 审批 body 展示配对工具调用的完整原始参数，在审批栏行预算内换行并计数溢出——审批是安全决策，此前 80 字符的卡片预览把目标路径截成省略号。
- `/mode` 列表经注册表的字典键解析内置预设文案并采用官方译文（0.1.7 起内置预设不再发布 name 与 description），用户自建元数据原样保留，输入过滤匹配解析后的文案。
- 源回放（resize 或 Ctrl+L）保留一个终端大小的真实活尾，不再把全部已落定行刷入原生回滚区——底部锚定不再释放，下一个动态帧仍显示最新历史。填充判定计入已绘制的头部。
- 更新探针在无环境提示时从运行中的 node 推导 npm 全局根（nvm、Homebrew 与系统布局），`/update` 不再把 link 挂载 checkout 上的已装宿主报成不存在。

## 设置迁移安全网

- dsh 0.1.7 废弃全局 `settings.yaml`：宿主把它一次性导入启动 profile 的补丁层，但导入先改名后写入、无重试，降级的首次启动可能把配置节滞留在改名文件里。启动时终端将改名文档与当前 profile 补丁层对比，把每个滞留配置节经进程内的设置服务重新导入——与供应商面板同一条经过校验、带文件锁并支持热重载的管道——配置无需手动操作或重启即可恢复。
- 仅写入补丁层完全没有配置行的节：用户已有配置不受影响，恢复过程幂等。恢复结果以单行通知呈现；各节的失败原因与可复制的恢复路径输出到 stderr，仅在设置服务不可用时回退为手动指引。凭据在全过程中不受影响。

## 提醒功能离开终端

- 0.1.7-rc.2 把提醒投递移到 web 会话控制栈：schedule 插件注入 `sessionController`，而后者的 `fileUploads` 与 `workspaceRegistry` 依赖仅存在于 web 组合。终端组合永远无法激活它——rc.1 上可用的 `schedule_create` 模型工具在升级后消失——上游自己的应对也是出厂禁用 schedule 与 time-context。本版本直接移除这两行，`/schedule` 命令、面板、折叠与文案键随之删除；读取旧会话时历史投递提示仍按普通用户行回放。在上游把投递与 web 栈解耦之前，终端没有提醒通道；当前最接近的形态是模型运行的后台 job 循环，但它不跨重启。

## 兼容性与升级说明

- 支持的宿主线为 `@deepseek-ai/dsh@0.1.7-rc.2`；旧线宿主按设计在启动时拒绝新 bundle，因此安装命令钉住宿主版本。
- `js-yaml` 移入运行时依赖（打进发布的 `lib/`），用户无需任何操作。
- npm 仍是主渠道；GitHub Release tarball 仍是受限网络的备用渠道。推送 tag 会创建 GitHub Release 资产，但不会执行 `npm publish`。

从 1.5.0 升级：

```sh
npm install -g @deepseek-ai/dsh@0.1.7-rc.2 dsh-code@1.6.0
dsh plugin --profile cli add dsh-code@1.6.0
```

然后 `/quit` 并重新启动。npm 两端齐备后，`/update` 一步完成同样的移动。GitHub tarball 安装可被 npm 命令覆盖；在 npm 尚未收录 1.6.0 期间，更新器会报告 tarball 安装新于 npm 并拒绝降级。
