# dsh-code 发布说明 - 1.3.0

## 概览

1.3.0 是基于 1.2.0 之后完整变更集的一次大范围终端可靠性与安全性发布。文件拖放现在能跨终端、跨平台路径格式变成真正的附件；面板统一独占键盘；会话切换、fork、历史召回和流式布局不再丢失或误投工作。会话删除也显著收紧：删除来源会话时保留 fork 分支，其他进程仍在写入时拒绝删除，`/delete` 变成绝不会误恢复对话的独立流程。宿主版本线仍为 `@deepseek-ai/dsh@0.1.5-rc.2`。

## 改进

### 文件拖放与附件

- 在 macOS、Windows 和 Linux 终端中，把文件或截图拖进输入框会变成与复制路径后粘贴相同的图片/文件附件。
- 带空格、Unicode 引号、shell 转义空格和百分号编码 `file://` 的文件名会解析为一条本地路径。
- 没有括号粘贴标记的拖放会保持为一个输入单元，不再逐字符拆分，从而避免在附件解析前触发 React 更新深度错误。
- 看起来像文件系统路径的草稿不再打开 slash 补全；残留的粘贴控制字节会在检查路径前移除。
- @ 补全没有新内容可接受、或草稿已经拼出高亮项时，回车不再被吞掉。

### 面板、命令与更新

- 所有面板使用同一套键盘归属约定。`/search` 的输入不再泄漏到草稿，回车不再把查询当提示发出，Esc 只关闭面板而不中断正在运行的回合。
- 打开面板时 Ctrl+C 与 Esc 一样关闭面板；没有面板时，原有的中断、清草稿与退出行为不变。被审批暂时顶掉的面板不会在回答后重新出现。
- 不接受参数的本地命令遇到多余文字时会提示 `usage: /name`，不再把文字转发给模型。
- 正在执行的 `/update` 安装不会随面板关闭而停止，再打开 `/update` 会接回同一个任务。重复确认不能启动第二个安装器，进度会保留，安装期间 Esc 继续锁定。
- 更新子进程启动失败时会正确清除共享运行状态，不再产生无人接收的清理 rejection。

### 会话与删除安全

- 删除根会话时只删除它委派的子代理。`/fork` 分支是独立对话，日志会保留；分支自己委派的子代理仍随分支删除。
- `/delete` 与 `/resume` 现在完全分离。在 `/delete` 中，回车只能进入明确的 `y` 确认；在 `/resume` 中，回车只恢复会话，旧的 `d` 删除快捷键已移除。
- 删除任何文件前，会为计划子树的每个成员获取持久化写句柄。因此另一个终端中仍打开的会话会阻止整个删除；部分加锁失败会完整回滚，不移除文件。
- `/delete <id>` 支持完整 id、唯一前缀和列表显示的唯一后缀；确认前会在需要时放宽列表范围以找到目标。
- 排队的会话切换进入激活阶段后，普通新提交会被明确拒绝，不再落到即将卸载的旧 agent 上再被丢弃。
- 接受 `/history` 条目会追加到现有草稿并保留已准备的附件；原草稿仍可通过召回走回。
- `/resume` 筛选会匹配显示标题以及 id、路径，主动搜索时会为更多行加载标题。
- `/fork` 会锚定到所在的已完成回合，包括两轮之间的元数据空隙。流式中执行 `/clear` 只清理已结算历史，当前回复继续输出。

### 布局、状态栏与界面语言

- 流式文本与结算后的 Markdown 在同一列折行；Ctrl+O 检查器会按当前终端宽度重新布局。
- 历史行数裁剪保留终端原生回滚缓冲；缩放和 Ctrl+L 仍执行预期的完整清理。
- 常见的 120 列宽度下，状态栏会先移除低优先级提示和身份字段，使上下文占用条保留更久。
- 大 token 数不再显示为 `1000K`，满一小时的耗时改用小时；读不到 manifest 时不再显示伪造的 `v0.0.0`。
- Rainbow 错误色不再与忙碌动画的实时颜色撞色；晚到的 `/effort` 查询不能覆盖更新的模型选择器。
- 会话、启动、复制/导出、设置告警、plan、goal、sandbox、欢迎页和 `/statusline` 标签现在一致跟随所选的中英文界面语言。

## 开发与发布保障

- 在整个依赖图中强制使用已修复的 `js-yaml`，CI 与发布任务会因已知生产依赖漏洞而失败。
- ESLint 现在把任何 warning 视为失败；React Hook 依赖已明确补齐；移除全局测试重试，使确定性失败保持可见。
- 覆盖率设置保守总体下限：行、语句、分支 82%，函数 88%。
- 发布任务校验 tag、`package.json` 版本和两份发布说明完全一致；手工 `npm publish` 也执行相同的审计、元数据、验证与构建门禁。
- GitHub Actions 固定到完整 commit SHA，CI token 只读，pnpm 在本地与 workflow 中统一固定为 12.4.1；已弃用的 tsdown 依赖配置完成迁移，bundle 字节不变。

## 兼容性与升级须知

- Harness peer 版本线没有变化，仍支持 `@deepseek-ai/dsh@0.1.5-rc.2`。
- 没有配置迁移。
- 操作变化：`/resume` 不再通过 `d` 删除。请使用 `/delete`，回车选择，再按 `y` 确认。
- npm 仍是主要渠道；GitHub Release tarball 仍作为受限网络的备用方式。推送 tag 会创建 GitHub Release 资产，但不会执行 `npm publish`。

从 1.2.0 升级：

```sh
npm install -g dsh-code@1.3.0
dsh plugin --profile cli add dsh-code@1.3.0
```

然后执行 `/quit` 并重新启动。从 GitHub tarball 安装的版本可以直接被 npm 命令覆盖。在 npm 尚未发布 1.3.0 时，更新器会提示 1.3.0 tarball 安装比 npm 新，并拒绝降级。
