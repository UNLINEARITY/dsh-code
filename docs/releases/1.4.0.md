# dsh-code Release Notes - 1.4.0

## Overview

1.4.0 turns provider sign-in and subagent observation into first-class workflows. Providers that offer a web subscription now present the choice between a plan sign-in and an API key directly on their setup page, and finishing a sign-in switches the route to the subscription channel automatically. The agents panel can attach to a subagent conversation as a full-screen live view that renders exactly like the main conversation and streams tokens in real time. The model panels render as aligned tables, and the runner now refuses to start against an incompatible Harness host instead of failing later in a session. The host line remains `@deepseek-ai/dsh@0.1.5-rc.2`.

## New workflows

### Provider sign-in as a channel choice

- The provider list keeps its layout and Enter behavior; the `l`/`o` login shortcuts and their footer hints are gone.
- A provider offering a web subscription heads its setup page with a channel layer: subscription or key. Tab on the subscription channel opens the browser sign-in (a provider with a single sign-in method starts immediately); Tab on the key channel keeps endpoint discovery unchanged.
- A finished sign-in switches the route to the subscription channel: the profile keeps no key reference, endpoint, or model list, the stored grant serves the official catalog, and the catalog's model list is written into the profile automatically.
- When both channels are configured, the setup page states which one actually serves requests, so a stored key can no longer silently shadow a plan sign-in.

### Live subagent observation

- From the agents panel, Enter opens the transcript preview as before, and a second Enter attaches the subagent conversation as the whole view.
- The attached view uses the same rendering pipeline as the main conversation: settled rows ride the same scrollback, token frames and durable events stream in from the live buses in real time, and the bottom carries an observing bar plus a status row naming the child.
- Esc or Ctrl+D returns to the agents list, Ctrl+C quits like the main session, and `r` reloads from the durable log. Duplicate events are dropped by sequence and stream frames are held until the history loads, so a stale streaming tail cannot reappear.
- The transcript preview itself gains a bordered near-fullscreen expansion with scrolling and refresh, which also serves the `/resume` transcript view.

## Interface improvements

- The model picker, the provider list, and the setup page's model rows render as aligned tables: provider names, states, key sources, login status, window capacities, and image markers line up across rows instead of drifting with field width. Editing brackets occupy the padding they replace, so selecting a value never shifts the columns.
- Chinese and English labels for the new surfaces follow the selected interface language, including the sign-in states, the observing bar, and the expanded document footers.

## Reliability

- The runner identifies the installed `dsh` host and compares its version and the bundled `dsh-agent`/`dsh-session` versions against the declared Harness snapshot before mounting. A mismatched host fails immediately with the actual versions listed and a fix hint, instead of running silently on unvetted upstream code. An unidentifiable host still starts without interference.
- The version gate's declared snapshot is contract-tested against the package manifest, so a future Harness bump cannot drift between the two.

## Development and architecture

- The terminal driver is now organized into focused modules: `panels/` for keyboard-owned modal surfaces, `ui/` for shared Ink atoms and contracts, `session/` for durable-session adapters, and `runner/` for the entry point's decisions and persistence IO. Each directory carries a machine-checkable dependency rule, and the public export surface of `src/index.ts` is unchanged.
- Session directory IO (picker projection, guarded deletion, export rendering) is injected through a narrow service interface and covered by real temporary-directory tests, including lease ordering, foreign-process holders, and both lease failure modes.
- The entry point's startup narrowing is a pure function covered by a boundary contract test, and the 4760-line App spec is split into seven surface-focused files over one shared fixture module with no test loss.
- The test suite grows to 81 files / 1132 tests with coverage floors held at 85% lines.

## Compatibility and upgrade notes

- No Harness peer line changed; `@deepseek-ai/dsh@0.1.5-rc.2` remains the supported host line. The new version gate fails fast only when the running host's own version disagrees with this build's declared snapshot.
- There are no configuration migrations.
- Workflow change: provider login and logout moved from the `l`/`o` list shortcuts into the provider's setup page. Open the provider with Enter, select the subscription channel, and press Tab to sign in; Enter on the subscription row signs out when already signed in.
- Deep-import paths under `dsh-code/src/` that moved into subdirectories resolve at their new paths; the package's documented entry points are unchanged.
- npm remains the primary channel; the GitHub Release tarball remains the fallback for restricted networks. A tag push creates the GitHub Release asset but does not run `npm publish`.

Upgrading from 1.3.0:

```sh
npm install -g dsh-code@1.4.0
dsh plugin --profile cli add dsh-code@1.4.0
```

Then `/quit` and start again. A GitHub-tarball installation can be overwritten by the npm command. Until npm carries 1.4.0, the updater reports that a 1.4.0 tarball install is newer and refuses to downgrade.
