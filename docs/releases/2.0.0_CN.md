# dsh-code 发布说明 - 2.0.0

## 概述

2.0.0 将终端升级到上游 `@deepseek-ai/dsh@0.2.0-rc.2` 版本线，并消除了两个被报告最多的视觉缺陷：流式输出期间整个终端持续频闪，以及终端尺寸调整后转录与 composer 之间出现稳定的空白行。频闪修复将每个 Ink 帧包裹在 DEC 2026 同步输出中，使终端只呈现最终帧状态；空白行修复让每次终端尺寸变化都触发一次源端重放来填满视口预算。本版本还新增了状态栏 git 分支实时指示、交互式钩子与 LSP 配置面板、统一面板按键语法下的子代理委派操作、经批准的插件 keystone 锁，以及覆盖全部面板的双语文案清理。

## 上游对齐至 0.2.0-rc.2

- 全部 Harness 依赖经过两次独立审计后升级到 0.2.0-rc.2（分别覆盖 0.2.0-rc.1 和 0.2.0-rc.2 两个上游版本）。0.2.0 版本线新增了共享 OTel 传输服务（`dsh-otel`）、带超时的 `ask_user_question` 工具、中断步骤的 pending 工具结果恢复（`ToolCallRecovery`）、以及 terminal-bash 的可选 `promptTailGraceMs`——全部为加法式，无破坏性接口变更。
- base 补丁在 `session-telemetry-otel` 之前新增一行 `otel`；telemetry collector 端点与导出分批的变化对终端面不可见（telemetry 保持在 FEEDBACK_ONLY 模式）。
- 两个 README 的安装命令显式锁定 `@deepseek-ai/dsh@0.2.0-rc.2`；`/update` 从本版本自身的 peer 依赖推导宿主版本线，launcher、bundle 与 profile 插件作为一个整体同步移动。

## 流式频闪消除（DEC 2026 同步输出）

- Ink 的 log-update 每帧擦除并全量重写整个动态区域且无行级 diff——流式期间即每秒约三十次全区域重写。帧级诊断探针实测最坏情况：当 Yoga 根高度达到终端行数时，Ink 内部的 clear-all 路径每秒触发至多五十七次，每次写入重打全部 Static 积压。
- 修复将 Ink 渲染所经的 stdout 流包装为同步输出委托对象：每个含 ANSI 擦除序列的帧与 DEC 2026 起始序列（`\x1b[?2026h`）和结束序列（`\x1b[?2026l`）拼接为一次原子写入。终端缓冲擦除后部分重写的中间态，只呈现最终帧——频闪在结构上不可见。不支持 DEC 2026 的终端静默忽略这些序列（优雅降级，无功能影响）。
- 包装器是纯对象而非 Proxy：Proxy 的 `Reflect.get` 会重入 Node 的 stdout getter 链导致栈溢出崩溃；将包装拆为多次顺序 `write()` 调用会三次重复触发完成回调，使 React 调度器以 "Should not already be working" 崩溃。两种失败模式均已记录在新的 `AGENTS.md` 中以防重现。

## 尺寸调整后的空白行修复

- 转录视口的 flush 游标只前进不后退。当终端变高但列宽不变（拖 VS Code 面板分隔条或 tmux 面板）时，预算增长但游标不动——锚定 Box 在转录尾部与 composer 之间填充真实空白行，直到足够的新内容沉淀填满空间。
- 任何终端尺寸变化（行或列）现在都在 75ms 去抖收束后触发同一清屏重放路径：Static 重挂载，flush 游标重置，已沉淀历史重新填充以满足新预算。重放经过合并——一次快速 resize 突发只产生恰好一次重放。
- 锚定面高度额外钳制到其内容行数（`min(dynamicRows, allLiveLines.length)`），即使重放落地前的一帧窗口内 Box 也不会在自身内容之下填充。

## 状态栏 git 分支实时更新

- 状态栏的分支标识现在无需重启即可跟随外部 checkout。仓库 `.git` 目录上的 `fs.watch` 监听器观察 HEAD 变化（分支切换与脱离 HEAD 移动），150ms 去抖重读，并通过订阅存储发布——状态行经 `useSyncExternalStore` 实时读取。Codex 的终端仅在对话轮边界刷新分支；本实现在空闲期间也保持实时。仓库外或脱离 HEAD 时标识保持缺席，不启动监听器。

## 交互式钩子与 LSP 配置面板

- `/hooks` 打开宿主 hooks 服务的完整交互面板：列出全部已注册钩子（Claude-code 与 Codex 桥接类型及其生命周期事件），在内存中切换本会话的启用/禁用，以及打开底层设置文件进行持久编辑。面板遵循统一按键语法：Enter 深入，Space 切换（安全可逆），Backspace×2 武装破坏性操作，`r` 刷新。
- `/lsp` 管理语言服务器：列出已配置服务器及其传输与状态，从目录安装，两次按键武装后移除，以及查看实时诊断。面板展示其将执行的安装命令，用户可手动复现。

## 子代理委派操作与统一面板按键语法

- `/agents` 面板新增对可继续子代理的完整发送消息与中断操作：选中任一列出的子代理，编写后续提示，无需离开面板即可送达。全部交互面板遵循同一经批准的按键语法——Enter 主操作，Space 安全可逆操作，Backspace 连按两次破坏性操作，`r` 刷新，esc/q 关闭。可由这五个键表达的操作不存在字母快捷键。

## 经批准的插件 keystone 锁

- `KEYSTONE_MODULES` 精确锁定本 bundle 自身补丁声明的 44 个模块名加上 `llm-pi-ai`。drift 测试遍历 base 补丁、bundle 补丁与全部 preset 文件，验证锁的「我们认为关键」概念与补丁实际命名一致。上游增删 base 行时，drift 测试以精确 diff 失败，更新锁是一个明确的双文件变更（锁加上 `tests/base-row-ids.json`）。

## 双语文案清理

- 面向内核官方中文 README 的术语标准，全部面板约六十个中文键与一百三十五处英文表述被重写：子代理、委派、钩子、压缩、权限预设、谱系、转录、实机验证。禁用词表（戏剧性比喻、俚语、军事用语）现已作为约定执行并记录在 `AGENTS.md` 中。
- 提交信息、日志条目与面板文案遵循同一双语标准：英文段落加语义镜像的中文段落，中文行文中保留代码标识符与英文技术术语。

## 开发文档

- `AGENTS.md`（新文件，272 行，十章）记录本发布周期学到的全部操作规则：stdout 变更后的真实终端启动测试（1282 项测试全过而 TUI 启动即崩）、轮询式时序断言（固定等待在并行负载下随机失败）、columns 减一反 autowrap 契约、stdout 回调单次写入规则、Proxy getter 递归、flush 游标单调性、版本对齐流程（含会话安全的 CLI 升级顺序）、十四条工具调用纪律（每条来自真实错误）、以及防止重复调查已知缺陷的未修问题登记。

## 渲染与布局修复

- `/search` 面板将每条结果渲染为两个物理行（主行加匹配片段）；视口现按该几何切片，矮终端不再使面板溢出其 maxHeight 预算。
- `NoticeLine` 截断从 `columns − 2` 改为 `columns − 3`，遵守全代码库无任何绘制行恰好填满终端宽度的契约（VS Code 在恰好最后一列自动换行，产生未记账行）。
- 流式尾部的正文列预算保留一个安全列，使 CJK 禁则悬挂（满行处最多超出列限两格）不越出终端边界。
- 分支监听器的测试轮询延长到显式 15 秒超时，在并行测试负载下不再与 vitest 默认 5 秒超时赛跑。

## 兼容性与升级说明

- 支持的宿主版本线为 `@deepseek-ai/dsh@0.2.0-rc.2`；旧版本线的宿主按设计在启动时拒绝新 bundle，安装命令因此显式锁定宿主版本。
- 1.x 的会话与配置原地迁移，无需手动步骤。1.6.0 的设置迁移安全网（搁浅的 `settings.yaml` 重新导入）继续覆盖从 0.1.x 宿主的升级。
- npm 仍为主渠道；GitHub Release tarball 仍为受限网络的备选。tag 推送创建 GitHub Release 资产但不执行 `npm publish`。
- `lite-preset/` 目录（本地开发 preset）不属于本发布；keystone drift 测试容忍其缺席。

从 1.6.0 升级：

```sh
npm install -g @deepseek-ai/dsh@0.2.0-rc.2 dsh-code@2.0.0
dsh plugin --profile cli add dsh-code@2.0.0
```

全局安装前请关闭所有正在运行的 dsh 会话（替换活跃进程正在读取的文件会导致 TTY 流上的 `read EIO` 崩溃——同一规则记录在 `AGENTS.md` §3.2）。
