# dsh-code Release Notes - 0.6.1

## Overview

Version 0.6.1 is a bug-fix release: it fixes the ghosted duplicates that
appeared when the deferred session was composed on your first input, and it
makes the global `deepseek`/`dsh-code` alias fail loudly when the cli profile
has not mounted dsh-code yet, instead of hanging.

## Fixes

### First-input rendering

- A bare launch now clears the screen before the placeholder tree is remounted
  with the real session id. Previously the old static header stayed on screen
  above the new one, painting two whale headers until a resize replayed.
- Queued prompt rows are kept in the live region instead of being flushed into
  the append-only transcript region. The inbox can retire them later, and an
  append-only flush cannot erase a retired row — the first message used to
  paint twice (queued row plus the durable row) until a resize.
- The welcome-header duplication and the duplicated first-message line are
  covered by App-level TTY regression tests that assert the exact physical
  screen content (one header, one message) after a cleared key-change remount.

### Launcher

- `deepseek` / `dsh-code` now checks the cli profile manifest before starting:
  when dsh-code is not mounted it prints the missing install step and exits
  with code 1, instead of launching a bare profile that keeps the process
  alive with no TUI runner.
- The launcher's missing-DSH hint no longer references the `@next` dist-tag.

## Testing

- 192 tests pass (`pnpm test`), including new regression coverage for the
  launcher preflight and for both first-input ghosting modes.

## Important notes

- No configuration or persisted-session migration is required from 0.6.0.
- Runtime requirements remain Node `^22.19 || >=24` and a compatible
  `@deepseek-ai/dsh` installation.
