# dsh-code Release Notes - 1.0.6 → 1.0.7

## Overview

1.0.6 and 1.0.7 carry the terminal onto the dsh `0.1.5-rc.2` line: the reading side adopts session-log format v3, with old sessions loading through an in-memory migration while the files on disk stay byte-for-byte unchanged; upgrading takes a single command - `/update` inside the terminal, or `deepseek update --apply` on the CLI - which aligns dsh-code, the global host, and every cli profile plugin together; and the official plugin set is enabled by default. The experience improves alongside: file attachments and fuzzy completion arrive, Shift+Tab gains a plan station, slash commands and prompts share one input history, IME composition and candidate windows follow the caret, and the terminal tab title tracks the session name and restores itself on focus.

## New features

### One command for the aligned upgrade

- Both `/update` inside the terminal and `deepseek update --apply` on the CLI upgrade the dsh-code bundle, the global host, and every installed cli profile plugin in a single operation, keeping all three on the same release line; community packages outside the @deepseek-ai scope are untouched.
- When the planned line is older than the installed host, the updater refuses the downgrade and prints the manual command instead of silently downgrading.

### The official plugin set, enabled by default

- Schedule reminders, time context (30-second snapshots), and the session-search index are on by default; session search ships read-only session tools, and the index is built on the first search.
- PTY and platform terminal tools, MCP servers, hooks bridges, and LSP ship as documented templates you enable as needed.
- Panels share one search-and-filter behavior, so list panels such as /mode no longer differ from each other.

### File attachments

- Paste and drag-drop split by type: images still go as image blocks, while other path-shaped entries (drive letters, UNC paths, `file://` URLs, or file names with a separator and extension) are sent verbatim as file attachments. Plain text, slash commands, and single words stay text, and a mixed paste is never split apart.
- Limits are explicit: up to 8 MiB per file and 8 files per message.
- File drafts work exactly like image drafts: a visible `[file: name · bytes]` marker, deletion follows the marker, Ctrl+C clears both, and the two kinds prepare in parallel on submit.
- The transcript, Ctrl+O details, and /export show file tags next to image tags on history rows and queued rows alike.
- Commands cannot carry attachments: submitting a slash line with attachments warns clearly, and the line still reaches the model as a prompt.

### Fuzzy completion and skills before the first message

- The `/` and `@` menus match by case-insensitive ordered subsequence with prefix priority, using the same ranking rules as the web client; `/md` finds `/mode`, and `@pk` lifts `package.json` to the top.
- The mention menu reorders without dropping results: matches rise first, and the remaining rows follow in their original order.
- Skills appear in the `/` menu from the very first screen, before any session exists; registry commands arrive with the first session, and built-in commands cover the common operations until then.

### A plan station in the Shift+Tab cycle

- The cycle runs workspace-write → danger-full-access → read-only → plan. Entering plan submits the upstream /plan command on top of the read-only preset, so plan mode is enforced at the tool layer rather than only prompted.
- Before the first session exists, the choice is held and takes effect with the opening message; the status bar names the station with a dedicated green plan marker, and row two keeps the blue ⧉ plan badge.

### Terminal tab title

- The tab shows "deepseek" until a session carries a name, then follows the session title; exiting the terminal restores the host default.
- The title is written through two channels (an OSC 0 sequence and the Windows process title): Windows Terminal needs no configuration, and inside the VS Code integrated terminal the TUI writes the `terminal.integrated.tabs.title: ${sequence}` setting once on first launch (an existing custom value is never overwritten, and the original file keeps a .dsh-backup copy).
- The title restores itself when the window regains focus: a background process sharing the console (a test runner, for example) may overwrite it, and focusing the terminal again brings it back.

### Shared recall history

- Typed slash commands and prompts share one history: Up/Down and the /history panel list both, entries persist across sessions, adjacent duplicates collapse, and the cap stays at 100 entries.
- For an unedited recalled entry, the arrow keys switch history entries from either text edge (start or end); moving the caret into the text returns to ordinary editing, where multi-line drafts move between their rows first and cross history at the edge; recalled entries and restored drafts keep the caret at the end of the line.

### IME caret anchoring

- IME composition and candidate windows follow the composer caret, so typing Chinese no longer lands at the screen edge or covers the status line; a recalled slash command no longer has its arrow keys taken by the completion menu.

### Provider configuration diagnostics

- A provider with broken configuration no longer disappears from /model: the error travels with the directory row, the unified configuration page surfaces it under the title in a warning tone, and the provider stays in the list, ready to repair.

### The active system prompt, visible

- /export emits the active system prompt as a collapsed block between the session header and the first record, so persona changes can be verified.

### Persistent catalog rows in /agents

- Every session-spawned subagent can appear as its own row, carrying the label and mode recorded by catalog events, alongside the live activity rows.

## Upstream alignment: dsh 0.1.5-rc.2

### Session-log format v3 on the reading side

- Logs written by earlier releases load through an in-memory migration; files on disk are never rewritten, and one session directory can hold several immutable generations.
- Live typing and the durable log are separated: the transcript renders streaming output by folding in-process assistant-stream frames, and settled replies restore their text and first-token timing from the embedded stream records; a replayed session matches the live view and its latency statistics.
- The system prompt becomes a first-class surface message; context estimation follows and stays accurate across compaction.
- `/fork` records lineage through the new contract fields; the legacy form is rejected by the released kernel.

### Host capabilities arriving with the line

- The model catalog adds DeepSeek-V41-Flash as the default for new sessions; model discovery lists over the anthropic-messages protocol and understands more gateway fields; a broken provider directory degrades into a visible diagnostic instead of vanishing.
- Proxy environment variables reach child processes; MCP tool pagination handles continuation cursors correctly; tool interrupts on Windows terminate the process group immediately through Job Objects.
- Model switches append a durable notice row to the transcript, and the kernel's per-session projection cache speeds up cold session-list reads.

## Fixed

- Opening the terminal on the new host showed a "Maximum update depth exceeded" warning before any input: the command registry produced a fresh list object even when the directory had not changed, chaining React updates; it now reuses the previous object when nothing changed and coalesces notifications, with the skills error path and the subagent catalog fold following the same rule.
- An attachment submission prepared before a queued session switch could land in the new session; submissions now carry the originating session identity, and the runner drops stale ones.
- A compaction summary could keep removed nodes counted in the system-prompt estimate; estimation now follows only the retained synthetic result.
- A late subagent catalog event could revert a finished subagent row to idle and leave it stuck in the panel; catalog events now keep the row's current state, and a full panel replaces the oldest non-running row.
- Session search skips a stored session it cannot parse instead of failing the whole search: the unreadable session logs a warning and rejoins automatically on later searches, with an equivalent upstream patch shipped under docs/upstream.
- An older local development copy refuses to pair with a newer global host instead of silently running a mismatched combination.
- /delete counts an unreadable directory as a failure instead of silently reporting success, and the unified configuration page counts its diagnostic row inside the panel height budget.

## Docs

- The troubleshooting page explains the shadowed global copy that can keep profile changes invisible, with steps to resolve it; upstream alignment audits live under docs/upstream.

## Verification

- 875 automated tests across 62 files, typecheck, build, peer-dependency checks, and `pnpm pack --dry-run` all pass; the tarball file list was inspected, and after a cli profile reinstall both `--help` and `--dump-config` were verified.
- IME caret anchoring, the terminal tab title, and the shared recall history were verified in a real VS Code integrated terminal with Microsoft Pinyin; sessions written by earlier releases load through the in-memory migration with disk files unchanged, and streaming and replay views match the live run.
