# dsh-code Release Notes - 0.9.0

## Overview

Version 0.9.0 focuses on session management and delegation. The `/resume` picker defaults to the current directory, sorts by last activity, and supports permanent deletion of a session together with its subagent threads through a composer-confirmed prompt. Subagents become observable while running and inherit the selected model: the new `/agents` feed, the `/subagent` panel, and an `agent/request` listener route delegated work onto the current model selection. Model picks persist as the global deployment default, the approval prompt is rebuilt as a decision dialog, completion accepts on Enter, and two subagent-panel defects (a React hooks crash and a duplicated effort suffix) are fixed.

## New features

### Session management

- `/resume` shows only the current directory's root sessions by default, using realpath-normalized path comparison; the cwd filter widens the listing to every workspace.
- The picker orders sessions by **last activity** — the JSONL artifact's modification time, falling back to creation time — and shows relative timestamps (`5m ago`, `2d ago`, dates).
- New `/delete` command and `d` key permanently remove a session **and its subagent threads** after a composer-confirmed prompt (`y delete · any other key cancels`, typed in the input box). The picker stays open and reloads immediately. The active and live sessions are refused, the JSONL layout is validated before any file is touched, and backends without a locatable artifact (SQLite) decline.

### Subagents

- Running subagents are observable: a bounded live-activity feed folds each child session into one row (label, state, last activity), a one-line summary sits above the composer, and the new `/agents` panel lists live and persisted children; Enter or `t` opens the full transcript.
- Delegated agents run on the **current model** rather than the launch-time default: a plugin-level `agent/request` listener mirrors the kernel's model-selection semantics onto subagent requests, and the new `/subagent` panel selects an explicit override (inherit row, model list, effort stage).
- Delegation tool cards include a bounded prompt preview, so the transcript shows what the child was asked before a result lands.

### Approvals

- The approval ask is a decision dialog instead of a bare y/n bar: a bold question header, a bounded command body with an overflow marker, and numbered options (Yes / No and tell it what to do differently / No, continue) driven by arrows plus Enter, y/n/d quick keys, digits, and Esc as an explicit rejection. Concurrent asks queue FIFO behind the on-screen one.

### Model defaults

- Every `/model` pick is saved as the **global deployment default** through the same `agentDefaultModel` service the web host uses; the choice survives restarts and is read by other surfaces, while the in-session switch is not rolled back when saving fails.
- `/model` and `/effort` open with the cursor on the current pick. A pick is validated immediately through `resolveCallConfig`, and `/effort` on a model with no advertised levels shows an explicit empty state.

## Improvements

- Completion menus (slash commands, mentions, bare paths) accept on **Enter** as well as Tab; a fully typed command still submits on return.
- `/resume` search is gated behind Ctrl+F, so typing no longer collides with navigation keys (Esc or Ctrl+F again exits, Enter commits).

## Bug fixes

- Opening and leaving the `/subagent` effort stage no longer triggers React's "Rendered fewer hooks than expected" (the input hook stays unconditional).
- The `/subagent` pick notice no longer duplicates the effort suffix (`…flash@max@max` becomes `…flash@max`).

## Behavior changes

- `/resume` defaults to the current directory; switch the cwd filter to see every workspace.
- Session ordering is by last activity rather than creation time.
- The picker's delete key is lowercase `d`; confirmation is typed in the composer.
- New commands: `/delete`, `/agents`, `/subagent`.

## Important notes

- Upgrading from 0.8.0 requires no configuration or persisted-session migration; no commands or settings were removed.
- Runtime requirements remain Node `^22.19 || >=24` and a compatible `@deepseek-ai/dsh` installation.
- Deleting a session also deletes its subagent threads and cannot be undone.
- On the release day, pnpm users should pin the exact version `dsh-code@0.9.0` because pnpm ignores packages published less than 24 hours ago.
