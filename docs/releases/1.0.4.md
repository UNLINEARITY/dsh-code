# dsh-code Release Notes - 1.0.4

## Overview

1.0.4 is the largest stability release yet, and it rebuilds provider management around real endpoint discovery. The intermittent keyboard freeze after approval prompts is eliminated at its root: the terminal stays in raw mode across all interface transitions, a lost paste-end marker no longer traps subsequent keystrokes, and the transcript scrollback can no longer become permanently frozen by an interrupted retry or command. The provider stage now opens one unified setup page — API key, endpoint, and the model list on a single screen — with a discovery stage that queries the live endpoint for the models it actually serves, so a gateway that adds a new model is one keystroke away from using it. Reasoning effort mappings gained an inline editor and a copy-from-model picker, the provider list groups configured entries at the top in the brand accent color, and Ctrl+C exits the entire model flow from any stage.

## New features

### Unified provider setup page

- The provider stage replaces the hidden Tab menu and the separate key panel with one page: the API key (masked, with its credential status shown inline), the endpoint URL (empty keeps the official default), and the model list with per-model context and output capacities all sit on the same screen. Up and down arrows walk the three zones; left and right cycle the selected model between context and output fields; digits edit the active field; the last row accepts hand-typed model ids; and Enter saves the key, endpoint, and models in one action.

### Real endpoint model discovery

- Pressing Tab from the setup page opens a discovery stage that queries the endpoint through the same model-discovery pipe the Web Models page uses. A typed key forces a direct probe of that URL, while an empty key uses the stored credential. A filled URL is never paired with the route id, so an installed official catalog can no longer shadow the gateway actual list — the probe always reaches the endpoint typed in the URL field.
- Results render as a checkable list: already-configured ids verify with a check mark but cannot be re-picked, and Enter adopts only the checked subset — selective import, never a bulk one. The list carries name, context window, and output cap when the endpoint discloses them; `f` refetches, Esc returns.

### Reasoning effort editor

- Model rows carry their reasoning declaration inline. Pressing `e` turns the selected row into an editor that accepts a compact level-to-wire grammar — space-separated pairs such as `low:low high:high max:max`, where `off:null` sends no reasoning parameter, the single token `false` disables the effort picker, and an empty submission restores inheritance from the installed catalog. Ctrl+U clears the draft, Esc cancels, and unknown or duplicated level names are rejected with one actionable message before anything is written.
- Pressing `c` opens a picker that lists every model with a declared mapping — settings declarations copied verbatim so dialect-specific wire spellings survive, catalog-advertised levels offered as identity maps — letting a newly added model adopt a proven mapping in a single keystroke, after which the background capability sync propagates the declaration across routes.
- Row labels surface the current state as `eff:N` (declared levels), `eff:off` (explicitly disabled), or `eff:~` (inheriting).

## Fixes

### Approval keyboard freeze

- The terminal dropped out of raw mode for a brief window every time the composer handed keys to the approval bar or back, stranding keystrokes in the line buffer until the next Enter. The terminal now stays in raw mode for the entire app lifetime, eliminating the freeze at its root.
- An unterminated bracketed paste (terminal defect or crash mid-paste) held every subsequent keypress hostage with no timeout and no escape. Held bytes are now released after a one-second shared window, keeping Esc and Ctrl+C reachable at all times.
- Pressing Enter on an empty `/mode` list crashed the process through an uncaught TypeError. The existence check now matches every other panel.
- The transcript scrollback could become permanently frozen when a retry or command was interrupted mid-flight: the still-running row blocked the boundary that separates settled history from the live viewport. The turn-end fold now finalizes any interrupted row so the boundary always advances.
- Ctrl+C was silently swallowed while an approval was pending; it now interrupts the running turn and withdraws the question.

### Terminal height and width budgets

- The completion menu height was not counted in the dynamic-row budget: typing `/` or `@` during streaming could push the content past the terminal edge and freeze the cursor above the top. Menu height is now reported through the same one-way channel as editor growth and deducted exactly.
- The approval and question panels could render as two full-height panels stacked, exceeding the terminal. When both are pending, the question panel takes the budget and the approval bar degrades to its bounded one-line form.
- Streaming text forced a ten-column minimum width on very narrow terminals, wrapping every row onto a second unbudgeted line. The width now shrinks with the physical terminal, and rows carry a truncate-end guard.
- The `/theme` panel rendered a fixed seven rows regardless of the available space, reaching terminal-height equality on a fourteen-row terminal where the entire screen is rewritten every frame. Theme rows are now sliced into the available space with cursor-reveal scrolling.

### Input and ordering correctness

- Backspace and forward Delete share the same key identity; the destructive queue-cancel action previously fired on a habitual Backspace on the empty composer. The cancel now requires the forward-delete key, matching the documented keybinding.
- Session-queue splices kept upstream in-place order: inserted ids were appended at the tail instead of splicing at the given position, so subsequent positional events could remove the wrong pending row.
- Submission delivery is serialized per session: a line with session mentions previously went through async preparation while a later plain line delivered synchronously past it, so the model saw the user messages in the wrong order.
- A failed screen handoff on session creation now rolls back the published session instead of reporting a failure while the new session is actually live.
- Switching agents after a successful catalog load retained the previous workspace skill and command rows on the next agent first-load failure; the catalog now clears when the owning agent never had a successful load.

## Improvements

### Unified model-flow keys

- The provider stage opens with Tab from the model list, matching the deeper-is-Tab convention the setup page already uses, and Ctrl+C leaves the whole model flow from any stage — model list, provider list, setup page, discovery, picker, and effort picker each consume the chord and close the overlay.
- The provider list sorts configured entries to the top behind a dim separator labeling the dormant tail. Configured rows render in the brand accent color so the in-use group reads at a glance.

### Additional hardening

- The Windows `deepseek update` command spawns `npm.cmd` through a shell, fixing both the install and version-check paths.
- Discovery results are deduplicated in endpoint order, preventing duplicate rows in the checkable list.
- The bare-launch `@` file search refreshes its index on a thirty-second window, so files created or deleted before the first session appear in (or leave) the mention menu.
