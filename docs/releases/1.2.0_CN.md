# dsh-code 发布说明 - 1.2.0

## 概览

1.2.0 恢复以 npm 作为主要安装与更新渠道。这一版带来回合运行中的排队与插队、`/usage` 用量面板，状态栏计量标签接入中英文界面；token 统计改用宿主上报的四个互不重叠的桶，状态栏与导出的数字随之更准。宿主版本线仍是 `@deepseek-ai/dsh@0.1.5-rc.2`。

## 新功能

### 排队与插队

- 回合运行中提交的消息不再打断当前回合：默认排队，等这一回合结束后作为新的一回发出。
- 空输入框按 `Tab` 在排队与插队之间切换。插队会在当前回合的下一个步骤边界交给模型，和当前这次请求一起处理。
- 提示符（`❯` / `↳`）、空输入框的提示文字、切换通知和 `/help` 都写明当前选的是哪一种；输入框有内容时 `Tab` 仍是补全。
- `/queue` 面板管理排队消息：回车改为插队、`e` 改文字（附件原样保留）、`d` 删除，`↑↓` / `PageUp` / `PageDown` / `g` / `G` 移动。
- 空输入框按 `Delete` 取消最新一条排队消息。
- 按 `Esc` 取消回合时，排队消息保留并接着发出，插队消息随这一回合丢掉。
- 会话区里每条提问整行带底色，颜色和标记说明它是怎么发出的（普通消息 / 排队 / 插队）。底色由主题色算出，换主题或重掷 rainbow 会跟着变；提问里粘贴的 ` ```diff ` 仍保留自己的红绿。

### 用量面板

- `/usage` 打开当前会话的用量：四个互不重叠的桶（未命中输入、缓存写入、缓存读取、输出）、缓存命中率，以及按模型合并的总量。
- 按回合明细：每个已完成回合的合计、未命中输入、缓存读取、命中率、缓存写入、输出、思考 token，以及实际计费的模型。
- 中途换过模型的回合按两个名字只列一次，不会重复计数；一次都没计费的回合不显示。
- 分组里若有回合没上报某个桶，数字按已上报的部分求和并标 `+`，表下写明这是下限。
- 数据取自宿主已有的 token 统计；未挂载该能力的部署会明确显示不可用，而不是显示 0。

## 改进

- 状态栏第二行（回合、步骤、模型耗时、延迟、tokens/秒、工具、缓存、入、出、上下文、`/mode`）随界面语言切换，`/language` 之后立即重绘，不必重启。
- 状态栏的「入」只算未命中缓存的输入，「缓存」同时给出缓存读取量与命中率，不再把所有缓存 token 折进一个输入数。
- `/export` 的统计行补上缓存写入。

## 修复

- 正常发送的消息不再被标成「排队」：只有提交那一刻回合已经在运行，才算排队或插队。

## 开发与质量

- 测试套件纳入 TypeScript 类型检查（`pnpm typecheck:tests`），测试替身与真实接口不一致会直接报错。
- ESLint 10 搭配依赖类型信息的规则集覆盖 `src`、`tests`、`scripts` 与根配置（`pnpm lint`），`src` 的 365 条问题清零。
- CI 增加这两道检查和一个只报告、不设门槛的覆盖率任务（语句覆盖 82.9%）。
- 一处行为变化：设置文件里不是对象的 JSON 现在会给出警告并回退默认值，不再静默处理。

## 更新与打包

- **npm 恢复为主渠道**：`npm install -g dsh-code@1.2.0`。装好后 `/update` 与 `deepseek update --apply` 都可用。
- GitHub Release tarball 保留为备用渠道（网络受限时使用），打 tag 时由 CI 构建并挂到 Release。
- 新增两个由宿主提供的 peer：`@deepseek-ai/dsh-token-meter` 与 `@deepseek-ai/dsh-session-projection`。dsh 默认已包含它们，不需要单独安装。
- 推 tag 只构建 tarball 并创建 GitHub Release，不会自动 `npm publish`。

## 升级须知

从 1.1.0 升级：

```sh
npm install -g dsh-code@1.2.0
dsh plugin --profile cli add dsh-code@1.2.0
```

然后 `/quit` 再启动。原先从 GitHub tarball 安装的，可以直接用上面的 npm 命令覆盖安装；npm 上还没有这个版本时，更新器会写明「新于 npm，不降级」。界面默认英文，中文界面执行 `/language zh`。
