# dsh-code Release Notes - 1.0.0

## Overview

Version 1.0.0 turns dsh-code into a complete daily-driver coding terminal over DeepSeek Harness. It adds durable image prompts, completed-turn session forks, file-oriented Git inspection and read-only review, response copying, provider configuration, background-job visibility, and release-aware launcher operations. The terminal surface is also substantially hardened: multiline editing, Kitty keyboard support, coherent reasoning folds, logical Markdown reflow, bounded long-session history, and width-aware layout keep the TUI responsive and predictable across Windows Terminal, narrow viewports, and sustained streaming.

## New features

### Daily coding workflows

- Start a session with an initial prompt and repeatable `-i, --image <path>` attachments. Harness stores the image bytes durably and session events retain content-addressed references, so prompts survive resume and export without a second attachment store.
- `/fork [event-seq]` creates a normal, resumable session from a completed turn while preserving the selected history and keeping the new conversation distinct from subagent threads.
- `/diff [--staged|ref]` parses unified patches into file sections, colors additions and removals, and switches files with the left and right arrows without truncating the patch used by review.
- `/review [--staged|ref]` submits a context-bounded review task under the `read-only` permission preset, while `/copy` copies the latest complete assistant response as UTF-8 text.
- The global launcher now provides `setup`, `doctor`, shell `completion`, and explicit `update` / `update --apply` operations in addition to forwarding normal TUI arguments.

### Harness rc.8 integration

- All Harness dependencies, peers, and development packages are aligned on `0.1.0-rc.8`; a manifest contract test prevents mixed release-candidate lines.
- `@` file completion now uses the official agent-scoped `fileReferences` service with bounded indexing and tool-result invalidation. Before the first session, the same search implementation indexes the launch directory.
- `/jobs` opens a read-only, refreshable view of the host background-job registry with state glyphs and elapsed time. `/todos` opens the complete three-state todo list in a bounded, scrollable panel.
- `web_fetch` is enabled in the shipped composition without requiring an API key, and the Cordis host runner is mounted so `/mode cordis` can resolve its inspection services.
- Interrupted assistant replies retain the rc.8 interruption marker in both live output and replay instead of appearing as ordinary completed answers.

### Models and provider configuration

- `/model` continues to add, rotate, and remove writable credentials through Harness; selecting a provider and pressing Tab now edits its endpoint URL, explicit model allow-list, and per-model context/output windows.
- The welcome header shows the version of the running `dsh` host alongside dsh-code's own version, making host/plugin mismatches visible before a turn starts.

## Terminal and rendering improvements

### Composer and keyboard handling

- The composer is now a bounded, grapheme-aware multiline editor. Shift+Enter inserts a newline, word and line navigation follow familiar terminal editor bindings, kill/yank operations preserve Unicode text, and long CJK drafts wrap within the viewport.
- Kitty CSI-u input is normalized before Ink parses it, including enhanced Ctrl+C, Ctrl+R, navigation keys, and legacy Home/End/Insert/Delete/PageUp/PageDown forms with modifiers.
- Panel search accepts multi-character IME commits and deletes whole graphemes. Bracketed paste recovery restores Enter submission after a missing end marker, and stray C0/DEL control bytes from Windows Terminal file drops are removed from draft data.
- Ctrl+C follows one explicit ownership contract: interrupt a running turn, clear a non-empty draft, then quit from an idle empty composer while restoring terminal keyboard and paste modes.

### Transcript and layout

- Reasoning and answer text share one authoritative assistant transcript entry. Ctrl+R applies one coherent fold state, avoids per-frame full-screen redraws while streaming, and performs only the required source-backed replay after the stream settles.
- Assistant paragraphs and lists remain logical Markdown content and reflow at the current terminal width while preserving inline styles. Subagent documents reuse the same renderer.
- Tool calls receive global ordinals that do not reset between turns; tool cards and nested errors use the same number. Detail rows use display-column-aware clipping and consistent continuation gutters for CJK, controls, and structured metadata.
- Transcript rows, tool details, and composer text now share one left edge. The context meter contracts to a minimum percent form before disappearing, preserving the permission badge and compact identity on narrow terminals.
- The bordered composer is replaced by a three-row shaded band, including the full-width DeepSeek model-switch animation, without increasing the terminal row budget.

### Long-session performance

- Settled terminal history is windowed at 3,000 physical rows by default, bounding replay time and Ink element memory while the event log, `/export`, Ctrl+O, and `/resume` retain the complete conversation. Set `DSH_SETTLED_ROWS=0` to disable the window or use another positive limit.
- Transcript and subagent notifications are frame-coalesced during sustained token streams, preventing React nested-update cascades without delaying sparse output.
- Replay uses indexed accumulation for tool, retry, and command updates, keeping long and orphan-heavy persisted sessions near-linear while matching the live projection.

## Bug fixes

- Streaming, idle, live-tail, and replayed reasoning now agree on the selected Ctrl+R fold state without flashing the header or rewriting immutable Static scrollback.
- Running tool rows settle immediately and keep their final status visible; settled history and queued messages no longer rebuild unnecessarily during animation or resize.
- Paste markers, stray escape bytes, surrogate pairs, terminal controls, bidirectional characters, tabs, and long structured tool fields no longer leak into the composer or break physical-width budgets.
- The status row preserves permission and identity priority on narrow terminals, and tool output no longer mixes two- and four-column continuation indents.

## Behavior changes

- New commands: `/fork`, `/diff`, `/review`, `/copy`, `/jobs`, and `/todos`.
- New startup option: repeatable `-i, --image <path>`.
- The rendered settled-history window defaults to 3,000 physical rows; complete history remains available through Ctrl+O and `/export`.
- The composer uses a three-row shaded band and supports multiline editing; Shift+Enter inserts a newline while plain Enter submits.

## Important notes

- dsh-code 1.0.x requires Node `^22.19 || >=24` and is built for the `@deepseek-ai/dsh@0.1.0-rc.8` plugin line. Keep the global host and plugin dependencies on that line.
- Upgrading from 0.9.1 requires no persisted-session migration. Harness remains a developer preview, so future host release candidates may require a matching dsh-code update.
- On the release day, pnpm users should pin `dsh-code@1.0.0` because pnpm ignores packages published less than 24 hours ago. npm installation is not affected.
