# dsh-code Release Notes - 1.0.8

## Overview

1.0.8 is a packaging hotfix for the 1.0.7 boot crash. The session-search tools that 1.0.7 enables by default import `@deepseek-ai/dsh-tool-session-query`, but the bundle declared that package only as an optional peer: the host CLI does not bundle it, and the profile's `autoInstallPeers: false` keeps pnpm from installing it, so every cli profile failed at boot with `ERR_MODULE_NOT_FOUND`. The package now ships as a real dependency of the bundle, the default-on plugin set works exactly as 1.0.7 documented, and the enable instructions for the same-class opt-ins no longer point at rows that cannot resolve.

## Fixed

- The cli profile boots again: the session-search package ships with the bundle (pinned to the same 0.1.5-rc.2 line) and resolves from the profile's own node_modules, verified against a simulated fresh profile install of the packed artifact.
- A new suite guard rejects any patch row that ships enabled over a module neither the bundle, its dependencies, nor the host install provides — the exact shape of the 1.0.7 crash, now caught before a release instead of in a user's terminal.
- `deepseek update --apply` no longer strands a half-finished upgrade: the host install and the dsh-code mount remain fatal, but a companion plugin without a build on the target line is reported with its exact manual retry command while the remaining carries finish; the final exit code still reports the incomplete pass.
- The missing-host guidance printed by `deepseek` and `deepseek setup` now pins both the harness line and the exact bundle release (`npm install -g @deepseek-ai/dsh@<line> dsh-code@<version>`) instead of pointing at an unpinned `dsh-code` that could mount a newer bundle beside an older wrapper.
- The launcher-update spec pinned the Windows rendering of `fileURLToPath`, so the automated suite could only pass on Windows; the assertion now covers both platform renderings and the suite is green on macOS and Linux.
- Fresh checkouts on pnpm 12.4+ refuse packages whose build scripts are not approved; koffi (the FFI dependency behind the JSONL persistence dev path) is now approved alongside esbuild.

## Upgrade notes

- 1.0.7 cannot boot in a cli profile — upgrade to 1.0.8 with `deepseek update --apply` on the CLI. The in-terminal `/update` panel needs a booting terminal, so it is unavailable to exactly the users this release rescues; the wrapper command is not, because it runs before any composition loads.
- If you applied the interim workaround of installing the package into the profile by hand, remove that entry after upgrading so the bundle dependency provides it: `pnpm --dir ~/.dsh/profiles/cli remove @deepseek-ai/dsh-tool-session-query`.

## Docs

- The README (English and Chinese) and the bundle patch comments now state which packages the host CLI bundles and which must be installed into the profile first: PTY terminal tools (`@deepseek-ai/dsh-tool-terminal`) and the LSP trio (`@deepseek-ai/dsh-lsp` / `dsh-lsp-stdio` / `dsh-tool-lsp`); enabling those rows without the packages fails the boot the same way 1.0.7 did.
- The install section explains the `npm warn install-scripts` prompt (the host ships prebuilt artifacts, so common platforms can ignore it) and points first troubleshooting at `deepseek doctor`.

## Verification

- The failing resolution was reproduced against the 1.0.7 packaging and re-verified green against a simulated fresh profile install of the 1.0.8 tarball; the new patch-row guard was confirmed to fail against the 1.0.7 manifest.
- typecheck passes and the automated suite covers 877 tests across 62 files; a small pre-existing family of timing-sensitive panel tests intermittently trips under full-suite parallel load and passes in isolation on every retry (observed on the 1.0.7 tree as well).
