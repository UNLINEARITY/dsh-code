# dsh-code 发布说明 - 1.0.1

## 概览

1.0.1 将完整终端 bundle 对齐到 DeepSeek Harness `0.1.1-rc.2`。本次加入基于新 authorization 内核的 provider 登录，让 `@` 补全和终端拖入自然地产生图片附件，显示支持图片的模型，并直接采用新的规范化图片请求管线，而不是在 dsh-code 中再造一套传输实现。

## 新功能

### Provider 登录

- `/model` 可以运行 Harness 当前注册的全部 provider 登录流程，包括 OAuth、设备码和交互式 API key。
- 在 Windows、macOS、Linux 上尽可能打开默认浏览器，同时在固定高度终端面板中保留 URL 与设备码。
- 支持文本、秘密输入和选项提问；秘密内容始终遮罩，URL/设备码提供明确的复制操作。
- Esc 取消登录。登录成功后刷新 provider 与模型目录；退出登录只删除授权 record，不删除 provider 配置。
- 手动 API key 继续保留；provider 配置明确引用 key 时仍以它为优先。

### 输入框图片附件

- 通过 `@` 选择 PNG、JPEG、WebP、GIF 时，会附加真实图片，prompt 文字只保留安全文件名。
- 向终端拖入一张或多张图片路径会产生相同附件，也允许用户明确拖入工作区之外的文件。
- 草稿图片按规范化路径去重；删除可见文件名标签会同步取消附件，也允许只发送图片。
- 加入图片时先验证，提交时才完成持久规范化；失败会保留草稿和待发送附件。
- `/model` 为支持图片的路由显示 `image`；选择纯文本模型时会提示历史图片将变成文字占位符。
- Transcript、Ctrl+O 和 Markdown 导出显示规范化尺寸；发生缩放时同时显示原始尺寸。

## Harness rc.2 集成

- 全部 Harness dependency、peer、开发依赖和发布时间例外均精确锁定到 `0.1.1-rc.2`。
- DeepSeek Vision 直接使用上游规范化 attachment、请求 variant、Files API 复用和 inline fallback。
- Provider 凭据刷新迁移到 `credentials/reference-updated`，授权 record 使用 `credentials/record-updated`。
- 重试耗尽后，终端同时保留 retry 过程和最终错误。
- 缓存命中率显示一位小数；结构化问题的自定义回答允许粘贴多行，但不新增换行快捷键。

## 维护与清理

- `/help` 与 slash 补全共用一份本地命令目录；Harness 提供同名命令时不再重复显示。
- Jobs 改为依赖抽象的 `dsh-jobs` 契约，不再直接绑定 process-local 实现包。
- 与上游完全相同的 Preset、Permission、Jobs 类型副本改用官方类型；具有不同降级或安全语义的本地适配层继续保留。
- Commander 15 与当前 dsh 宿主保持一致，减少全局安装中的重复大版本。

## 重要说明

- dsh-code 1.0.1 要求 `@deepseek-ai/dsh@0.1.1-rc.2`。Harness 版本线有意采用精确锁定，请勿与 rc.8 或未经审计的后续候选版本混用。
- rc.2 已删除旧 DeepSeek 配置项 `maxRequestImageBytes`。
- Files API 解析失败时，上游 adapter 会静默回退到 inline 图片；Harness 当前没有向终端客户端公开回退事件。
- 已有会话无需迁移。Credentials provider 会自动升级可识别的旧 `.credentials.yaml`，首次启动 rc.2 前应先备份该文件。
