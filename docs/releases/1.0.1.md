# dsh-code Release Notes - 1.0.1

## Overview

Version 1.0.1 aligns the complete terminal bundle with DeepSeek Harness `0.1.1-rc.2`. It adds provider sign-in through the new authorization kernel, makes image attachment a natural part of `@` completion and terminal file drops, exposes image-capable models, and adopts the new normalized image request pipeline without creating a second transport implementation.

## New features

### Provider sign-in

- `/model` can run every provider login flow registered by Harness, including OAuth, device-code, and interactive API-key methods.
- Sign-in opens the default browser on Windows, macOS, and Linux when possible while retaining the URL and device code in a bounded terminal panel.
- Text, secret, and select prompts are supported; secrets remain masked and URL/code values have an explicit copy action.
- Esc cancels a login. Successful sign-in refreshes the provider and model directories, while logout removes only the authorization record and preserves provider configuration.
- Manual API keys remain available and retain precedence when a provider profile explicitly names one.

### Images in the composer

- Selecting PNG, JPEG, WebP, or GIF files through `@` attaches the real image and leaves only a safe filename in prompt text.
- Dropping one or more image paths into the terminal creates the same attachments, including explicitly dropped files outside the workspace.
- Draft images are deduplicated by normalized path. Removing the visible filename token detaches the image, and image-only messages are valid.
- Image validation happens when a file is added; durable normalization happens at submission. Errors keep the draft and pending attachments intact.
- `/model` labels image-capable routes with `image` and warns when a text-only model will receive historical images as text placeholders.
- Transcript, Ctrl+O, and Markdown export show the normalized dimensions and the original dimensions when scaling occurred.

## Harness rc.2 integration

- Every Harness dependency, peer, development package, and release-age exception is pinned exactly to `0.1.1-rc.2`.
- DeepSeek Vision uses the upstream normalized attachment, request-variant, Files API reuse, and inline fallback pipeline.
- Provider credential refresh follows the renamed `credentials/reference-updated` event, and authorization records follow `credentials/record-updated`.
- The terminal keeps retry rows and the final error after retries are exhausted.
- Cache-hit percentage displays one decimal place, and structured question custom answers accept pasted multiline text without introducing a newline shortcut.

## Maintenance

- `/help` and slash completion now use one local command catalog; local commands no longer appear twice when Harness exports a command with the same name.
- Jobs depend on the abstract `dsh-jobs` contract rather than the process-local implementation package.
- Exact upstream Preset, Permission, and Jobs type copies were replaced with official package types; local adapters with distinct behavior remain.
- Commander 15 matches the current dsh host and avoids a duplicate major version in global installations.

## Important notes

- dsh-code 1.0.1 requires `@deepseek-ai/dsh@0.1.1-rc.2`. The Harness package line is intentionally exact; do not mix it with rc.8 or a later unreviewed release candidate.
- The old DeepSeek setting `maxRequestImageBytes` no longer exists in rc.2.
- Files API resolution silently falls back to inline images inside the upstream adapter. Harness currently exposes no fallback event to terminal clients.
- Existing sessions require no migration. The credential provider upgrades recognized legacy `.credentials.yaml` documents automatically; back up the file before the first rc.2 launch.
