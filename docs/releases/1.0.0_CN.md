# dsh-code 发布说明 - 1.0.0

## 概览

1.0.0 将 dsh-code 补全为基于 DeepSeek Harness 的日常编码终端。新增持久图片提示、按已完成 turn 创建会话 fork、按文件浏览 Git diff 与只读 review、回复复制、provider 配置、后台任务可视化以及感知发布版本的 launcher 操作。终端表面也完成系统性加固：多行编辑、Kitty 键盘协议、统一的思考折叠、逻辑 Markdown 重排、有界长会话历史和宽度感知布局，使 TUI 在 Windows Terminal、窄终端和持续流式输出下保持响应与可预测性。

## 新特性

### 日常编码工作流

- 启动会话时可直接提供初始 prompt，并重复使用 `-i, --image <path>` 附加图片。Harness 持久化图片字节，会话事件只保留内容寻址引用，因此恢复与导出无需引入第二套附件存储。
- `/fork [event-seq]` 可从已完成 turn 创建普通、可恢复的新会话，保留选定历史，同时不会把新会话误归类为子代理线程。
- `/diff [--staged|ref]` 将统一 patch 解析为按文件分段的视图，为新增与删除行着色，并支持左右方向键切换文件；用于 review 的完整 patch 不会被面板截断。
- `/review [--staged|ref]` 在 `read-only` 权限预设下提交有上下文上限的审查任务；`/copy` 以 UTF-8 文本复制最近一条完整助手回复。
- 全局 launcher 在转发普通 TUI 参数之外，新增 `setup`、`doctor`、shell `completion` 以及显式的 `update` / `update --apply` 操作。

### Harness rc.8 集成

- 全部 Harness dependencies、peer dependencies 与开发依赖统一到 `0.1.0-rc.8`，并通过清单契约测试防止候选版本线再次混用。
- `@` 文件补全切换到官方、按 agent 隔离的 `fileReferences` 服务，使用有界索引并随工具结果失效刷新；首次会话创建前，同一套搜索实现会索引启动目录。
- `/jobs` 提供宿主后台任务注册表的只读、可刷新视图，显示状态图标与运行时长；`/todos` 在有界可滚动面板中展示完整三态待办列表。
- 发布组合默认启用无需 API key 的 `web_fetch`，并挂载 Cordis host runner，使 `/mode cordis` 能解析其运行时检查服务。
- 被中断的助手回复在 live 与 replay 中都保留 rc.8 interruption 标记，不再伪装为普通完成回复。

### 模型与 provider 配置

- `/model` 继续通过 Harness 添加、轮换和移除可写凭据；选中 provider 后按 Tab，可编辑 endpoint URL、显式模型白名单以及逐模型的上下文/输出窗口。
- 欢迎头同时显示正在运行的 `dsh` 宿主版本与 dsh-code 自身版本，使宿主/插件不匹配在首次 turn 前即可发现。

## 终端与渲染改进

### 输入框与键盘处理

- 输入框升级为有界、感知字素的多行编辑器。Shift+Enter 插入换行，单词与行级导航遵循常见终端编辑快捷键，kill/yank 操作保持 Unicode 文本完整，长 CJK 草稿会在视口内正确换行。
- Kitty CSI-u 输入在 Ink 解析前完成归一化，覆盖增强版 Ctrl+C、Ctrl+R、导航键，以及带修饰键的 Home/End/Insert/Delete/PageUp/PageDown legacy 形式。
- 面板搜索支持 IME 多字符提交并按完整字素删除。括号粘贴缺失结束标记时会恢复 Enter 提交；Windows Terminal 文件拖放携带的杂散 C0/DEL 控制字节会从草稿数据中直接移除。
- Ctrl+C 采用单一明确的所有权契约：运行中中断 turn，草稿非空时清空草稿，空闲且输入为空时退出，并完整恢复终端键盘与粘贴模式。

### 转录与布局

- 思考与回答共用一个权威 assistant transcript entry。Ctrl+R 采用统一折叠状态，流式期间不再逐帧整屏重绘，只在流收敛后执行必要的一次源重放。
- 助手段落与列表保持为逻辑 Markdown 内容，按当前终端宽度自然重排并保留行内样式；子代理文档复用同一渲染器。
- 工具调用获得跨 turn 不重置的全局序号，工具卡与嵌套错误共用同一编号。详情行按显示列截断，对 CJK、控制字符与结构化元数据使用一致的续行缩进。
- 转录行、工具详情与输入框文字统一左边缘。窄终端下 context meter 会先收缩到最小百分比形态，再整体移除，从而优先保留权限角标与压缩后的身份信息。
- 输入框由边框改为三行背景色带，DeepSeek 模型切换动画覆盖完整色带，同时不增加终端行预算。

### 长会话性能

- 终端中的已结算历史默认以 3000 物理行为窗口，限制重放时间与 Ink 元素内存；事件日志、`/export`、Ctrl+O 与 `/resume` 仍保留完整会话。设置 `DSH_SETTLED_ROWS=0` 可关闭窗口，也可指定其他正整数上限。
- 持续 token 流期间，transcript 与 subagent 通知按帧合并，避免 React 嵌套更新级联，同时不拖慢稀疏输出。
- replay 对工具、重试与命令更新使用索引累积，使长会话和包含大量孤立事件的持久记录保持近线性处理，并与 live 投影结果一致。

## 修复

- 流式、空闲、live tail 与 replay 中的思考内容统一遵循当前 Ctrl+R 折叠状态，不再闪烁 header 或回写不可变的 Static 滚动历史。
- 运行中工具行会即时结算并显示最终状态；动画与缩放期间不再无谓重建已结算历史和排队消息。
- 粘贴标记、杂散 escape 字节、代理对、终端控制字符、双向控制符、Tab 与过长结构化工具字段不再污染输入框或破坏物理列宽预算。
- 窄终端状态栏会优先保留权限与身份信息，工具输出不再混用两列与四列续行缩进。

## 行为变化

- 新命令：`/fork`、`/diff`、`/review`、`/copy`、`/jobs`、`/todos`。
- 新启动参数：可重复使用的 `-i, --image <path>`。
- 已结算历史的终端渲染窗口默认上限为 3000 物理行；Ctrl+O 与 `/export` 仍可访问完整历史。
- 输入框改用三行背景色带并支持多行编辑；Shift+Enter 插入换行，普通 Enter 提交。

## 重要说明

- dsh-code 1.0.x 要求 Node `^22.19 || >=24`，并面向 `@deepseek-ai/dsh@0.1.0-rc.8` 插件线构建。请让全局宿主与插件依赖保持在该版本线。
- 从 0.9.1 升级无需迁移持久会话。Harness 仍处于 developer preview，后续宿主候选版本可能需要配套更新 dsh-code。
- 发布首日，pnpm 用户应固定使用 `dsh-code@1.0.0`，因为 pnpm 会忽略发布不足 24 小时的包；npm 安装不受影响。
