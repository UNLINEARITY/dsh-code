# dsh-code 发布说明 - 1.0.7

## 概述

1.0.7 聚焦「升级体验与输入细节」：`/update` 一条命令同时升级 dsh-code、全局宿主与 cli profile 插件；官方插件集开箱装配，schedule 提醒、time context 与会话检索索引默认可用，PTY 终端工具、MCP 服务器、hooks 桥与 LSP 以文档化模板按需启用；Shift+Tab 新增 plan 档位并在工具层强制 plan 模式。输入与终端细节全面打磨：/ 指令并入召回历史，中文输入法的组合窗与候选窗跟随 composer 光标，终端标签默认显示 deepseek 并跟随会话名、被后台进程改写后焦点回到终端即恢复。版本线对齐到 dsh 0.1.5-rc.2（上游 rc.2 为 Web 端反馈与文件改进及版本号提升，对终端无需源码适配）。修复包括会话搜索跳过无法解析的存量会话、旧本地检出拒绝与新全局宿主配对。

## 新特性

### /update 一条命令对齐升级

- 一条命令同时升级 dsh-code bundle、全局宿主与 cli profile 已装插件，保持三者的版本线一致。

### 官方插件集开箱装配

- schedule 提醒、time context（30 秒快照）与会话检索索引默认挂载；会话检索提供只读会话工具，索引在首次搜索时惰性打开。
- PTY 与平台终端工具、MCP 服务器、hooks 桥、LSP 以文档化模板按需启用；@deepseek-ai 作用域之外的社区包不受影响。
- 各面板查询键统一，/mode 等列表面板的过滤体验一致。

### Shift+Tab 新增 plan 档位

- 循环为 workspace-write → danger-full-access → read-only → plan；进入 plan 在 read-only 预设上提交上游 /plan 注册表命令，plan 模式在工具层强制生效，而不只是提示层约束。
- 首会话建立前该选择以待定状态持有并随开场消息落实；状态栏以专用绿色 plan tone 命名档位，第二行保留蓝色 ⧉ plan 标记。

### 终端标签标题

- 标签默认显示 deepseek，会话命名后跟随会话名；退出终端恢复宿主默认标签。
- 双通道写入（OSC 0 序列 + Windows 进程标题）：Windows Terminal 开箱生效；VS Code 集成终端由 TUI 自动对齐一次 `terminal.integrated.tabs.title: \${sequence}` 用户设置（已有自定义值绝不覆盖，原文件保留 .dsh-backup 备份）。
- 焦点回到终端时自动恢复标签：共享控制台的后台进程（如测试运行器）改写标题后，点回终端即复原。

### 共享召回历史

- 输入的 / 指令与提示词共用同一份召回历史：Up/Down 与 /history 面板并列展示，跨会话持久，相邻重复折叠，100 条上限不变。
- 遍历门槛重写：未编辑的召回条目，光标在行首或行尾都可双向遍历；光标移入内部即进入普通编辑（多行草稿先在行间移动，到视觉边缘再跨历史）；召回条目与恢复草稿的光标保持在行尾。

### 中文输入法光标锚定

- 组合窗与候选窗跟随 composer 光标，中文输入不再飘到控制台边缘或压住状态栏；召回的指令条目不再被补全菜单抢占遍历。

## 修复

- 会话搜索跳过无法解析的存量会话：单个损坏会话不再使全部查询失败，被跳过的会话记录警告并在后续搜索自动重试，待可解析它的宿主版本安装后自动回到索引；等语义上游补丁随 docs/upstream 一并提供。
- 旧本地检出拒绝与新全局宿主配对，避免以不一致的版本组合静默运行。

## 文档

- 故障排查页新增 shadowed 全局副本的说明与处理步骤。

## 验证

- 875 项自动化测试（62 个文件）、typecheck、build 与 `pnpm pack --dry-run` 全部通过；tarball 文件清单已核对。
- IME 锚定、终端标签与共享召回历史均经真实 VS Code 集成终端 + 微软拼音实测。
