# dsh-code Release Notes - 1.0.7

## Overview

1.0.7 focuses on the upgrade experience and input details: `/update` upgrades dsh-code, the global host, and the cli profile plugins in one command; the official plugin set ships preconfigured, with schedule reminders, time context, and the session-search index available out of the box while PTY terminal tools, MCP servers, hooks bridges, and LSP ship as documented opt-in templates; Shift+Tab gains a plan station that enforces plan mode at the tool layer. Input and terminal details are polished throughout: slash commands join the recall history, IME composition and candidate windows follow the composer caret, and the terminal tab shows deepseek by default, follows the session title, and restores itself after a background process overwrites it. The release line aligns to dsh 0.1.5-rc.2 (upstream rc.2 carries web-client feedback and file refinements plus version bumps, requiring no source adaptation in the terminal). Fixes include session search skipping unreadable stored sessions and an older local checkout refusing to pair with a newer global host.

## New features

### One-command aligned upgrade with /update

- One command upgrades the dsh-code bundle, the global host, and every installed cli profile plugin together, keeping all three on the same release line.

### The official plugin set, preconfigured

- Schedule reminders, time context (30-second snapshots), and the session-search index mount out of the box; session search ships read-only session tools, and the index opens lazily on the first search.
- PTY and platform terminal tools, MCP servers, hooks bridges, and LSP ship as documented opt-in templates; community packages outside the @deepseek-ai scope are untouched.
- Panel query keys are unified, so filterable panels such as /mode behave consistently.

### A plan station in the Shift+Tab mode cycle

- The cycle now runs workspace-write → danger-full-access → read-only → plan; entering plan submits the upstream /plan registry command on top of the read-only preset, so plan mode is enforced at the tool layer, not only prompted.
- Before the first session exists the choice is held as pending state and lands with the opening message; the status badge names the station with a dedicated green plan tone, while row two keeps the blue ⧉ plan marker.

### Terminal tab title

- The tab shows "deepseek" until a session carries a name, then follows the session title; exiting the terminal restores the host default.
- Two delivery channels are covered (an OSC 0 sequence plus the Windows process title): Windows Terminal works out of the box, and inside VS Code the TUI aligns the `terminal.integrated.tabs.title: ${sequence}` user setting once (an existing custom value is never overwritten, and the original file keeps a .dsh-backup copy).
- Focus-in restores the label: a background process sharing the console (a test runner, for example) may overwrite the title, and clicking back into the terminal restores it.

### Shared recall history

- Typed slash commands and prompts share one recall history: Up/Down and the /history panel list both, entries persist across sessions, adjacent duplicates collapse, and the 100-entry cap is unchanged.
- The navigation gate was rewritten: an unedited recalled entry walks history from either text edge (start or end), while the caret inside the text returns the arrows to ordinary editing (multi-line drafts walk their rows first and cross history at the visual edge); recalled entries and restored drafts keep the caret on the trailing edge.

### IME caret anchoring

- IME composition and candidate windows follow the composer caret, so typing Chinese no longer pops the candidate bar at the console edge or over the status line; recalled command entries are no longer trapped by the completion menu.

## Fixed

- Session search skips a stored session it cannot parse instead of failing the whole search: the unreadable session logs a warning and rejoins automatically on later searches, with an equivalently patched upstream module shipped under docs/upstream.
- An older local checkout refuses to pair with a newer global host instead of silently running a mismatched combination.

## Docs

- The troubleshooting page documents the shadowed global copy that can keep profile changes invisible.
